## 1. 目的・背景（Why）

目的タグは **G2（副業で稼ぐ）**。既存スキル群は「作る」と「投稿する」を担うが、
**収益にする**部分がどこにもない:

- sns-ops-team / sns-auto-posting: 投稿の企画〜実行はできるが、投稿がどこに読者を運び、何で収益化するかの構造を持たない。
- article-writer: note 記事は書けるが、アフィリエイトリンクの管理・PR 表記・記事から収益への計測がない。
- biz-ops-guard: プロダクト成立性の判断枠組みはあるが、「発信で稼ぐ」事業自体には未適用。

本設計は「集客（SNS）→ 深い記事（note）→ 収益点（アフィリエイトリンク）→ 計測 →
継続/撤退判断」という**事業構造**を確定させ、それを回す運用スキル
`affiliate-monetization` を実装可能な粒度に落とす。コードはほぼ書かない。
成果物の中心はスキル（SKILL.md + テンプレート3枚）と運用データファイルの契約。

### 5.4 biz-ops-guard 適用（本書で記入済み — 実装時はこれを SKILL.md 同ディレクトリに転載）

対象は「Ryo の収益化構造」で、直接のユーザーは Ryo 1人。ただし biz-ops-guard の
趣旨に従い、**プロダクト = 発信コンテンツ、ユーザー = 読者**と読み替えて適用する。

**Go/No-Go ラダー回答:**

1. 想定ユーザー3人: ①AIツールを業務導入したい非エンジニアの会社員 ②副業目的で AI ツール比較を検索する20代 ③Ryo 自身（自分が過去に欲しかった記事を書く）。固有名詞は公開リポジトリ方針（biz-ops-guard）により属性表記。→ **Yes**
2. 乗り換え理由1文: 「公式ドキュメントや企業メディアを読み比べずに、実務で使った当事者の選定理由と失敗込みの評価が1記事で分かる」。代替 = 公式Doc・企業比較メディア・ChatGPT に直接聞く。→ **Yes**
3. 導入5分・3ステップ: 読者側は X で見て note を読むだけ（0ステップ）。運用者側は ①スキル導入 ②ヒアリング5問 ③funnel-config 生成、で15分。**運用者側は5分超 → 初回のみと割り切り「意図的に無視」**。
4. 保守上限: 週120分（コンテンツ制作込み。funnel-config に宣言）。→ **Yes**
5. 最初の10ユーザーへの経路: 既存 X アカウント（sns-ops-team 運用中）からの誘導。→ **Yes**

**ビジネス運用面シート:**

- 一文価値提案: AI/IT ツール導入検討者が、比較メディアの読み比べをせずに、実務者の本音評価1記事で選定できる
- 想定ユーザー（3人）: 上記ラダー1のとおり（属性表記）
- 代替手段と乗り換え理由（1点）: 企業比較メディア → 実務の一次体験（失敗込み）があること
- 導入: 読者0ステップ / 運用者3ステップ・15分 / 前提条件: ASP 審査通過・X/note アカウント
- 保守: 予算 週120分 / 壊れる要因: ASP案件終了によるリンク切れ・X の外部リンク仕様変更・ステマ規制の運用強化 / 廃止基準: §6.4 の撤退基準
- 運用: 定常作業: 週次バッチ（制作〜転記〜判断）120分 / 失敗通知経路: 週次レビュー時に link-registry の URL を目視確認（自動監視は作らない） / 1利用あたりコスト: 0円（API課金なし）
- 配布チャネルと最初の10ユーザー: 既存 X アカウント（到達期限: 公開後2週）
- 収益/回収: 読者は無料。ASP 成果報酬で回収。報酬水準は断定しない（要調査: hermes-relay）
- 記録する指標: kpi-log.md の9列（新規=note誘導クリック、再利用=note PV、紹介=発生件数 に対応）
- 意図的に無視すること: 運用者側導入の5分超過（初回のみ）／Instagram・Threads・TikTok（Phase 1 では対象外）／ASP API 連携

## 6. 処理フロー

### 6.1 事業構造（確定）とその根拠

```
[集客] X ポスト（sns-ops-team 制作 → sns-auto-posting 投稿）
   │  プロフィール固定リンク + ポスト内 note リンク
   ▼
[受け皿] note 無料記事（article-writer 制作。冒頭に PR 表記）
   │  記事内アフィリエイトリンク（link-registry で採番）
   ▼
[収益点] ASP 成果報酬（Amazon アソシエイト / A8.net / もしもアフィリエイト から審査が通ったもの1社）
   ▼
[計測] 週次で kpi-log.md に転記 → 判断表で継続/調整/撤退
```

根拠:
- **集客と収益点を分ける理由**: X は外部リンク付きポストのリーチが抑制されるとされる（真偽と度合いは実装時に hermes-relay で最新状況を調査。§11）。またポスト単体ではPR表記・比較情報を載せる文字数がない。深い比較・体験は note に置き、X は誘導に徹するのが両プラットフォームの制約に整合する。
- **Phase 1 を X × note にする理由**: X は sns-auto-posting で API 投稿が実装済み・sns-ops-team の運用資産（戦略ファイル・キュー）が既にある。note は article-writer が制作を担える。TikTok/Threads は投稿手段も制作資産もなく、検証開始までのコストが最大になるため後回し（§6.2）。
- **ジャンル = AI/IT ツール紹介にする理由**: 選定基準は「①自分が一次体験を書ける ②購買行動につながる検索・比較需要が既知 ③YMYL（医療・金融・法律）でない」の3条件。AI/IT ツールは3条件を満たす Ryo の唯一の領域。別ジャンル追加は Phase 1 の撤退基準を満たさず継続できた後のみ。

### 6.2 フェーズ分割（確定）

| Phase | 範囲 | 開始条件 |
|---|---|---|
| 1 | X × AI/IT ツール × note 無料記事 × ASP 1社 | スキル実装完了 + ASP 審査通過 |
| 2 | note 有料記事の追加、ASP 2社目、Threads 追加 | Phase 1 で確定件数が 1 以上（金額不問） |
| 3 | TikTok（動画）追加 | Phase 2 の月間確定額が Phase 3 制作コストを正当化するとユーザーが判断した時（数値基準は Phase 2 実績を見て設定） |

Phase 2 以降の詳細設計は本書に含めない（Phase 1 の実績が前提を変えるため）。

### 6.3 週次バッチ（Phase 1 の定常運用。スキルが案内する手順）

1. **入力**: funnel-config.md + sns/<アカウント>/sns-strategy.md → **処理**: 今週の note 記事1本のテーマと X 誘導ポスト案を sns-ops-team の週次バッチに乗せる（企画指示に「note 記事 URL への誘導を CTA にする」を追加するだけ。sns-ops-team の工程は変更しない） → **出力**: post-queue.md の draft 行
2. **入力**: 記事テーマ + link-registry.md → **処理**: article-writer で note 記事を制作。本スキルは (a) 冒頭 PR 表記文言（funnel-config の確定文） (b) 挿入するリンク（link_id 指定） (c) リンク挿入位置 = 「商品の評価を述べたセクションの直後」 を article-writer への指示に含める → **出力**: 完成原稿（note へは手動投稿。article-writer の契約どおり）
3. **入力**: 公開済み note 記事 URL → **処理**: link-registry.md の貼付先列を更新。post-queue.md の該当 draft を Ryo が approve → sns-auto-posting が投稿 → **出力**: 投稿完了
4. **入力**: ユーザーが転記する実績数値（X アナリティクス / note ダッシュボード / ASP 管理画面） → **処理**: kpi-log.md に1行追記し §6.4 の判断表を適用 → **出力**: 判断（継続/調整/撤退）と根拠1〜3行

### 6.4 KPI と判断表（確定。数値は初期値であり、4週ごとのレビューで改訂可 — 改訂は kpi-log.md 末尾に日付つきで記録）

週次で見るのは kpi-log.md の9列。判断は上から順に最初に該当した行を適用する:

| 条件 | 判断 |
|---|---|
| 作業分が2週連続で 120 を超過 | **縮小**（投稿数を減らす。それでも超過なら撤退検討） |
| 直近4週の note誘導クリック合計 < 10 | **調整**（集客側の問題。ポストの CTA・テーマを sns-ops-team の振り返りで変更） |
| 直近4週の note誘導クリック合計 ≥ 10 かつ リンククリック合計 = 0 | **調整**（記事側の問題。リンク位置・商品選定を変更） |
| 開始から12週経過で 発生件数累計 = 0 | **撤退検討**（ジャンルまたは受け皿を変えて再スタートするか、凍結するかをユーザーに提示。惰性で13週目に入らない） |
| 開始から24週経過で 確定額累計 = 0 円 | **撤退**（Phase 1 構造を凍結し、学びを biz-ops-guard の定期レビュー形式でシートに追記して閉じる） |
| 上記いずれにも該当しない | **継続** |

### 6.5 既存スキルとの役割分担（契約。重複実装禁止）

| 工程 | 担当 | 本スキルとのインターフェース |
|---|---|---|
| 投稿の企画・執筆・レビュー | sns-ops-team | 企画指示に「note 誘導 CTA」を追加。post-queue.md の書式は変更しない |
| X への投稿実行 | sns-auto-posting | approved 行の投稿。本スキルはステータスを触らない |
| note 記事の制作 | article-writer | PR 表記文言・link_id・挿入位置を指示として渡す |
| SEO 記事（検索流入） | owned-media | Phase 1 では使わない（note は SNS 流入前提）。Phase 2 以降の検討事項 |
| 成立性の定期レビュー | biz-ops-guard | 月1レビューの3指標は kpi-log.md の列で代替（§5.4） |
| 本スキル | affiliate-monetization | ジャンル選定・ファネル定義・リンク台帳・PR 表記の強制・週次判断 |

## 7. エッジケース

| ケース | 期待挙動 |
