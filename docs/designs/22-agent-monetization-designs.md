## 0. 本設計書の位置づけ

2026-07-11 の Hermes 調査（`automation/results/20260711T185445Z-fable5-latest-ai-monetization-retry6.md`）
で得た収益化候補4案を、**実装するためではなく、実シグナル（実在の第三者からの「使いたい」1件）を
取りに行ける状態にするため**に設計する。biz-ops-guard の大原則により、
**4案とも実シグナル獲得までコードは1行も書かない。**

本設計の根拠には使わない（Epistemia対策）。使う前提は「最新モデルで agent

## 1. 案① ハイブリッドagentリサーチ→コンテンツ自動生成の提供

**価値提案**: 個人事業主・一人社長が、外注ライターに月数万円払わずに、
週次の業界リサーチ＋発信素材（X投稿・ブログ下書き）を受け取れる。

### 経路判定: ファストパス（半日でコアデモ可）

SaaS を作るのではなく、**既存の hermes-relay + article-writer をそのまま人力オーケストレーションして
「代行サービス」として1人分のアウトプットを作る**のがコアデモ。半日で1顧客分のサンプル
（リサーチ要約1本＋X投稿5本＋ブログ下書き1本）を作れる。SaaS化はユーザー10人超まで対象外。

### ビジネス運用面シート（ドラフト）

- 価値提案: 個人事業主が、外注ライター/自力のネタ探しをせずに、週次の発信素材一式を受け取れる
- 実在ユーザー3人: (a) X運用を自力で続けられていないコーチ/コンサル業 (b) 発信したいが時間がない士業 (c) EC/D2Cの一人運営者
- 実シグナル: **未獲得（本設計の次工程）**
- 導入: 手順数 0（納品物を受け取るだけ）/ 所要 0分 / 前提条件: 対象業界のヒアリング1回
- 保守運用: 週60分/顧客（クエリ調整＋品質検収）/ 壊れる要因: hermes-relay障害・モデル出力劣化 / 失敗通知経路: 自分が検収するので即時 / 廃止基準: 保守週120分超が2週連続
- 配布: 既知の個人事業主に直接DM → note記事 / 最初の10人 / 到達期限 公開後8週
- 収益/回収: 月額1〜3万円/顧客（代行）。無料期間はサンプル1式のみ
- 指標: 継続月数 / 顧客からの紹介数
- 意図的に無視すること: SaaS化・自動課金・マルチテナント（10顧客まで人力＋半自動で回す）
- 悪魔の代弁者: §6参照

### ピッチ文（実在3人送付用）

「あなたの業界の今週の動き（Xと一般Web）を毎週調べて、X投稿5本とブログ下書き1本にして
月曜朝に届けるサービスを試作してます。1週間分を無料で作るので、試しに受け取ってもらえませんか？」

### 実シグナル獲得計画

1. ユーザーが知っている個人事業主3人（利害関係のない第三者を優先）を選ぶ
2. 上のピッチを送る（文面調整可）
3. 「試したい」返信1件で実シグナル成立 → 半日でサンプル1式を作り納品 → 反応をシートに記録

### 失敗シナリオ

| # | 失敗シナリオ | 早期警報サイン | 設計上の対策 |
|---|---|---|---|
| 1 | 無料サンプルは受け取るが誰も金を払わない（発信素材への支払い意思が低い） | サンプル納品後「有料なら不要」が2/3件 | 無料納品時に価格を先に提示し、反応を課金前提で測る |
| 2 | 品質検収に週60分超かかり、実質ライター業になり時給が最低賃金を割る | 1顧客の検収が2週連続90分超 | 検収チェックリスト化。超過2回で価格改定か廃止 |
| 3 | 生成物の事実誤り（捏造引用）を顧客がそのまま投稿し信用毀損 | 検収で捏造を1回でも検出 | 根拠URL必須＋検収で全URL開いて確認。確認不能な主張は納品から削除 |

## 3. 案③ 経済・業界分析エージェント（自分用が主、レポート販売は派生）

**2026-07-11 ユーザー表明により位置づけ変更**: 「金融系・経済分析AIが自分で欲しい
（就活・学習にも使う）」という本人需要が確定。よって案③は
**(a) 自分用の経済・業界分析エージェント**（主。自分専用ツールのため biz-ops-guard 対象外、
yagni-guard のみ適用。実シグナル不要で着手可）と、
**(b) その運用実績を土台にした定期レポート販売**（従。こちらは従来どおり実シグナル必須）
の2段構成とする。

**(a) の方針 — 作る前に既存を調べる（M-003: 実物優先）**:
一から作らず、まず既存OSS（金融データ取得・経済分析エージェント系リポジトリ）の流用可否を
hermes-relay で調査する（§5 クエリC）。既存リポジトリ＋本リポジトリの `biz-analysis` スキル
（市場・競合分析の既存資産）＋hermes-relay 調査系を組み合わせるのが既定路線。
責務境界: `biz-analysis` は個別企業・競合の分析、本件はマクロ経済・業界構造・金融データが対象。
重複が出たら統合を検討する（棚卸しルール）。

**(a) の完成条件（自分用・検証可能な形）**:
- 業界または経済テーマを1つ指定すると、根拠URL付きの分析メモ（現状整理・構造・反証候補）が返る
- 数値は実取得値のみ（推測補完は「未検証」明記。Epistemia対策）
- 就活の業界研究1業界分を実際にこれで作れる

以下の (b) レポート販売シートは実シグナル獲得後にのみ発動する。

**価値提案（b）**: 特定業界の個人投資家・事業者が、複数ソースを自力で漁らずに、
週次で業界サプライチェーン・競合動向の整理レポート（根拠URL付き）を読める。

**法的制約（設計の前提）**: 個別銘柄の売買推奨・個別助言は金融商品取引法の投資助言・代理業に
該当し得るため**恒久的にスコープ外**。扱うのは不特定多数向けの業界動向整理のみ。
レポート冒頭に「投資助言ではない」旨を毎号明記する。

### 経路判定: ファストパス（半日でコアデモ可）

業界を1つ選び（ユーザーの土地勘がある業界。未定なら実シグナル送付前にユーザーが決める）、
hermes-relay で調査 → 整理レポート1号分を note 無料記事として半日で作れる。

### ビジネス運用面シート（ドラフト）

- 価値提案: ◯◯業界ウォッチャーが、毎週のニュース漁りをせずに、根拠URL付きの動向整理を10分で読める
- 実在ユーザー3人: (a) 特定業界に集中投資している個人投資家 (b) 同業界で働く会社員（業界動向を会議で話す立場） (c) 同業界向けに営業する人
- 実シグナル: **未獲得（本設計の次工程）**
- 導入: 手順数 1（noteフォロー）/ 所要 1分 / 前提条件: なし
- 保守運用: 週90分（調査クエリ実行＋検収＋整形）/ 壊れる要因: hermes-relay障害・ネタ枯れ / 失敗通知経路: relay の status:error / 廃止基準: 週90分を2回連続超過、または読者増ゼロが2ヶ月
- 配布: note（無料数号→有料 or メンバーシップ）+ X連携 / 最初の10人 / 到達期限 公開後8週
- 収益/回収: noteメンバーシップ 500〜1,000円/月。無料期間は実績（G2/G3）で回収
- 指標: フォロワー増 / 有料転換数 / 継続率
- 意図的に無視すること: 個別銘柄推奨（法的リスク）・複数業界同時展開・専用サイト
- 悪魔の代弁者: §6参照
