## 1. 目的・背景（Why）

Claude Fable 5 の無料期間は 2026-07-07 で終了する。無料期間中の既定運用は「メインセッションを
Fable のままにしてよい」（model-switcher §運用ルール5）だったが、7/7 以降この特例は消える。
Fable は入力 $10 / 出力 $50（1M トークンあたり）で、同じ仕事を Sonnet の約 3 倍・Haiku の約 10 倍
のコストになる。無料前提で組んだ運用をそのまま続けると課金が跳ねる。

**今日（2026-07-06）の実例が移行の必要性を実証した**: Fable で設計作業中に Fable の使用量上限に
到達し、作業が止まった。Opus 4.8 に切り替えて設計を継続し、実装は Sonnet に渡す想定に移った。
教訓は2つ — ①Fable を設計常用に使うと枠切れで作業が中断する ②切替判断が遅れると中断時間が延びる。

本設計書は、7/7 以降の**確定運用**を1枚に固定する:
- タスク種別ごとの推奨モデル（設計＝Opus、実装＝Sonnet、整形/一括変換/転記＝Haiku、最難関のみ Fable）
- 高単価モデル（Opus / Fable）の使いどころを絞る判断基準
- 並列サブエージェントの model 継承によるコスト膨張への対策
- 1タスク開始時のモデル宣言チェックリスト

既存の model-switcher スキルは「タスク→モデルを選ぶ**汎用ロジック**」を提供する。本設計書は
その汎用ロジックを 7/7 以降の状況（Fable 有料化・Opus が設計常用上限）に固定した**確定運用**で、
model-switcher の一般論では決まらない「配分の既定値」と「実運用チェックリスト」を上乗せする。

## 5. データ構造

該当なし（スキーマ・ファイルフォーマットを定義しない運用ドキュメント）。以下 §5.1〜5.4 は
本運用の確定内容そのもの。

### 5.1 タスク種別 → モデル対応表（7/7 以降の確定値）

| タスク種別 | モデル | 切替の実行手段 |
|---|---|---|
| 既定（何も宣言しない状態の主力） | Sonnet 5 | `.claude/settings.json` に `"model": "claude-sonnet-5"` |
| アーキテクチャ設計・技術選定・要件定義の壁打ち | Opus 4.8 | セッション頭で `/model opus`、フェーズ終了で `/model claude-sonnet-5` に戻す |
| スキル作成・プロンプト設計・設計書執筆 | Opus 4.8 | 同上 |
| 難しいデバッグ・原因調査 | Opus 4.8 | 同上（解決したら Sonnet に戻す） |
| 設計書に基づく実装・通常コーディング・リファクタ | Sonnet 5 | 既定のまま（`/model` 不要） |
| コードレビュー・PR チェック・記事執筆 | Sonnet 5 | 既定のまま |
| 大量データ整形・一括変換・転記・単純要約/分類 | Haiku 4.5 | サブエージェントの `model: haiku` 指定（メインは切り替えない） |
| Opus でも行き詰まった最難関（設計判断・難デバッグ） | Fable 5 | その場で `/model claude-fable-5`、解決後**即** `/model claude-sonnet-5` か `/model opus` に戻す |

**7/7 前後の変化点（無料期間との差分）**:
- 無料期間中の特例「メインを Fable のままでよい」は 7/7 で失効する。7/7 以降、Fable は
  「Opus で詰まった最難関だけ」に絞る例外モデルになる。
- 設計・要件定義・スキル作成の常用上限は **Opus 4.8**（Fable の半額）。設計だからと反射的に Fable を選ばない。

### 5.2 高単価モデルを絞る判断基準（確定）

model-switcher の3つの質問（失敗コスト・試行回数・判断難度）を、7/7 以降は次の閾値で運用する:

**Opus 4.8 を使う条件（両方を満たす時だけ）**:
1. 失敗コストが高い（間違えると後工程全体に波及／手戻り大）、**かつ**
2. 判断が難しい（曖昧さ解消・トレードオフ比較・長い推論が必要）。

- どちらか一方だけなら **Sonnet 5** で始める（詰まってから上げる）。
- 「回数が多いだけ（試行回数のみ）」は Opus ではなく **Haiku** に寄せる。

**Fable 5 を使う条件（例外）**:
- Opus 4.8 で実際に行き詰まった最難関タスクに限る。「難しそう」の予感では上げない。**Opus で1周
  試して詰まった実績**を条件とする。
- 使ったら解決後**即**戻す。Fable 稼働を持ち越さない（枠切れ・課金膨張の主因）。

### 5.3 並列サブエージェントの model 継承対策（確定）

サブエージェントは **model 未指定だと親セッションのモデルを継承する**。設計フェーズでメインが
Opus のとき、実装サブエージェントを model 指定なしで並列 fan-out すると、全エージェントが Opus で
走り、コストが並列数分だけ膨張する。対策:

- **実装をサブエージェントに並列委譲する時は、全エージェントに `model: sonnet` を明示する**
  （継承任せにしない）。バルク処理（整形・変換・転記）は `model: haiku` を明示する。
- **配分の既定**: 設計は Opus **少数**（原則メイン1セッション、または Opus エージェント1個）、
  実装は Sonnet **多数**（並列 fan-out は Sonnet）。「設計を並列で N 個回す」はしない。
- **fork サブエージェントは model 継承を上書きできない**（fork は常に親モデルを継承する）。
  安いモデルへの fan-out に fork を使わない。安くしたい並列作業は `general-purpose` / `claude` を
  `model: sonnet` または `model: haiku` で明示して起動する。

### 5.4 モデル運用チェックリスト（確定・6項目）

1. **1タスク開始時にモデルを宣言する** — model-switcher の分類表→3つの質問で種別を判定し、
   「このタスクは <種別> 相当なので <モデル> で進める」と1行宣言してから着手する。現モデルと
   推奨が一致していれば「Sonnet で続行」と宣言するだけでよい。
2. **設計フェーズに入ったら `/model opus`、終わったら `/model claude-sonnet-5` に戻す** —
   フェーズ境界でだけ切り替える（プロンプトキャッシュ無効化を避けるため往復を最小化）。
3. **並列実装をサブエージェントに出す時は全エージェントに `model: sonnet` を明示する** —
   親が Opus でも継承させない（§5.3）。
4. **バルク処理（10件以上×同一手順×判断不要）は `model: haiku` サブエージェントに委譲する** —
   メインのモデルは切り替えない。
5. **Fable は Opus で詰まった時だけ `/model claude-fable-5`、解決後は即戻す**（§5.2）。
6. **Opus / Fable 稼働中は token-saver（full）と yagni-guard（full）を自動適用する** —
   単価が最高のモデルで応答の無駄・過剰実装を出さないため（model-switcher §Fable/Opus 使用時の自動適用）。

**振り返り（週次・手動）**: 「Sonnet で詰まって Opus に上げた回数」を数える。多ければ設計/難デバッグの
切替基準を早め（予感段階で Opus）に緩める。少なければ現状維持。ツール化しない（YAGNI・§2.2）。

## 6. 処理フロー

本書は「運用の実行フロー」を定義する。1タスクあたりの流れ:

1. **入力**: 新しいタスク着手／タスク切り替え。
2. **判定**: §5.4 項1 のモデル宣言（分類表→3つの質問→§5.2 の閾値）。
3. **切替（必要時のみ）**:
   - 設計・難デバッグ・スキル作成 → `/model opus`（§5.4 項2）。
   - 実装・レビュー・記事 → 既定 Sonnet のまま。
   - バルク → `model: haiku` サブエージェント（§5.4 項4、メインは変えない）。
   - 並列実装 → `model: sonnet` を全エージェントに明示（§5.3）。
   - Opus で詰まった最難関 → `/model claude-fable-5` → 解決後即戻す（§5.2）。
4. **自動適用**: 切替先が Opus/Fable なら token-saver＋yagni-guard を開始（§5.4 項6）。
5. **フェーズ終了**: Opus/Fable から Sonnet へ戻す。切替往復はフェーズ境界に限定。
6. **出力**: タスク完了。週次で §5.4 の振り返りを回す。

分岐条件は上記3の各行が確定値。表にないタスクは model-switcher の3つの質問→§5.2 閾値で決める。

## 7. エッジケース

| ケース | 期待挙動 |
|---|---|
| 高単価モデルの使用量上限に到達（今日の実例の再現） | 即 `/model opus`（Fable 上限時）または `/model claude-sonnet-5`（Opus 上限時）にフォールバックし、作業を止めない。上限到達を待たず §5.2 で Fable 常用を避けて枠を温存する |
| 設計フェーズ終了後もメインが Opus のまま実装に突入 | 実装着手前に `/model claude-sonnet-5` へ戻す（§5.4 項2）。戻し忘れは §8-2 の早期警報で検知 |
| 親が Opus のまま実装サブエージェントを model 未指定で並列起動しかけた | 起動前に全エージェントへ `model: sonnet` を付与する（§5.3）。付与できない fork は使わない |
| バルク処理だがメインを Haiku に `/model` 切替してしまいそう | メインは切り替えず `model: haiku` サブエージェントに委譲する（メインのコンテキスト・モデルを汚さない） |
| 1タスク内で難所と単純作業が混在 | 難所だけメイン（Opus）、残りを `model: sonnet`/`haiku` サブエージェントに委譲（§5.3）。頻繁な `/model` 往復はしない |
| 「難しそう」だが Opus で未着手のまま Fable に上げようとする | Fable は Opus で1周詰まった実績が条件（§5.2）。予感段階では上げず Opus で始める |
| model-switcher の価格・特例と本書の記述が食い違う | 価格の一次ソースは model-switcher の表。運用の配分既定は本書。§9 で両者を整合させる |
