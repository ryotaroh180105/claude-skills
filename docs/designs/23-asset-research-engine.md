## 0. 品質の定義 — 「資産運用にそのまま使える」を分解する

依頼は「クオリティの高いもの」。品質を構成する要素を先に確定し、各要素を設計のどこが
担保するかを固定する。**このシステムの品質は「予測の当たり外れ」ではなく
「意思決定プロセスの規律」で決まる**。価格予測は誰にもできない（AIにも）。
個人投資家がプロに劣後する原因は予測力ではなく、①根拠の弱い情報で動く
②反証を見ない ③記録しないので学習しない ④感情で規律を破る、の4つであり、
本システムはこの4つを構造的に潰す。

| # | 品質要素 | 素人がやりがちな失敗 | 本設計での担保箇所 |
|---|---|---|---|
| Q1 | 一次データ主義 | ニュース・SNSの又聞き数値で判断 | データ層は政府統計・中央銀行・法定開示のAPIのみ（§4）。ニュースは「仮説の入口」扱いでデータで裏取り |
| Q2 | 検証可能性 | 出典のない「〜らしい」で判断 | 全数値に取得元URL＋取得日時を機械付与（§5.2）。取得失敗は「未検証」明記（Epistemia対策） |
| Q3 | 反証の強制 | 買いたい理由だけ集める（確証バイアス） | 分析メモに bear case・反証条件・「何が起きたら自分が間違いか」欄を必須化（§5.3）。空欄では保存できない |
| Q4 | ベンチマーク反実仮想 | 個別アイデアを絶対評価する | 全アイデアに「全世界インデックスを黙って買う場合と比べてなぜ勝るか」欄を必須化（§5.3） |
| Q5 | 意思決定ジャーナル | 過去の判断根拠を忘れ、成績を検証しない | 判断時に仮説・期待・レビュー日を事前登録し、月次で答え合わせ（§5.4, §6.4）。的中率と誤りパターンを蓄積 |
| Q6 | リスク規律の外生化 | その場の気分でポジションサイズを決める | IPS（投資方針書）に配分レンジ・1銘柄上限・損失許容を**分析の前に**固定（§5.1）。全提案は IPS 照合ゲートを通る（§6.5） |
| Q7 | 行動バイアス防御 | 急騰銘柄に飛びつく／暴落で狼狽売り | 新規アイデアは24時間クーリングオフ、FOMO チェックリスト、暴落時は「IPS を読み上げる」モード（§6.5） |
| Q8 | コスト・税制の最適化 | リターンばかり見て手数料・税金を無視 | 全提案に NISA/特定口座の別・想定コストの欄（§5.3）。日本の個人で確実に効く唯一のレバーとして常時表示 |
| Q9 | ソース汚染への耐性 | 実在URLだが虚偽の内容を信じる | 独立2ソース裏取り＋一次情報優先（設計書22のレッドチーム所見を全案共通ルール化済み）。単一ソースは「未確認」隔離 |
| Q10 | 継続可能性 | 熱意が冷めて3週で止まる | 定常運用は月次1回・30分に圧縮（§6.4）。日次の義務を作らない |

**作らないと決めるもの（品質のための不作為）**: 価格予測モデル、売買シグナル生成、
自動売買、他人への助言機能。予測はできない前提を崩すといずれ Q1〜Q9 全部が腐る。

## 1. 目的・背景（Why）

Ryo が自分の資産運用（NISA・投信・日米株を想定。実際の対象は IPS 面談で確定）の
意思決定を、勘とSNSではなく一次データと記録された規律で行えるようにする。
副次目的: 就活用の業界研究（同じ分析パイプラインの出力を流用）、金融・経済の学習。
自分専用ツールのため biz-ops-guard 対象外。yagni-guard を適用し Phase 制で最小から作る。

## 2. スコープ

### 2.1 やること

- **Phase 1（コア。これだけで運用開始可能）**
  - IPS（投資方針書）の対話作成・保存・照合
  - マクロダッシュボード（金利・インフレ・イールドカーブ・PMI・USDJPY・VIX 等を実データで一覧化）
  - 個別テーマ/銘柄/業界の分析メモ生成（§5.3 の固定8セクション）
  - 意思決定ジャーナル（事前登録→月次答え合わせ）
  - データ取得スクリプト: FRED / e-Stat / EDINET / SEC EDGAR / yfinance
- **Phase 2（拡張。Phase 1 を4週使ってから）**
  - Alpha Vantage または FMP の MCP サーバー接続（無料枠）
  - hermes-relay 連携: ニュース・X センチメントを「仮説の入口」として分析メモに取り込む
  - 就活用出力モード（業界研究レポート形式）
- **Phase 3（自動化。Phase 2 の後）**
  - 月次レビューの Routine 化（loop-engineering の6要素で設計）
  - マクロダッシュボードの週次自動更新と閾値アラート

### 2.2 やらないこと（明示的スコープ外）

- 価格予測・リターン予測モデル（原理的に不可能。作ると Q1〜Q9 が腐る）
- 売買の自動執行・証券会社API接続（執行は人間。誤発注・認証リスクを負わない）
- 他人向けの助言・レポート販売機能（設計書22の案③bの管轄。金商法の助言該当性はそちらで管理）
- バックテスト基盤（YAGNI。ジャーナルの前向き検証で代替。欲しくなったら別設計書）
- OpenBB Platform の全面導入（AGPLの重依存。Phase 1 は軽量フェッチャで足りる。フェッチャが6本を超えて管理が破綻したら Phase 2 で再検討、と `ponytail:` を残す）
- ポートフォリオの自動リバランス計算の最適化（乖離%表示まで。最適化理論はやらない）

## 4. データ層（外部連携の確定リスト）

| ソース | 用途 | 認証 | 無料枠 | 信頼度 | 障害時フォールバック |
|---|---|---|---|---|---|
| FRED API | 米金利・インフレ・失業率・VIX等 約80万系列 | 無料キー | 実質無制限 | 一次（セントルイス連銀） | IMF/World Bank API（キー不要） |
| e-Stat API | 日本の政府統計（CPI・GDP・毎月勤労統計） | 無料キー | 十分 | 一次（総務省） | 日銀時系列統計（CSV直取得） |
| EDINET API v2 | 日本企業の法定開示（有報・四半期・大量保有） | キー不要 | 十分 | 一次（金融庁） | なし（唯一の法定ソース。落ちたら「未取得」明記） |
| SEC EDGAR | 米企業の法定開示（10-K/10-Q） | キー不要（UA明示） | 10req/s | 一次（SEC） | なし（同上） |
| yfinance | 株価・投信基準価額・為替の時系列 | キー不要 | 非公式・突然壊れる | 二次 | stooq CSV → Phase 2 で Alpha Vantage MCP |

価格の採用ルール（レッドチーム所見1）: 価格は **yfinance と stooq の2系統を常時取得して突合し、
終値乖離1%超なら値を出さず `PRICE_MISMATCH`** とする（片系統のみの値は判断に使えない）。
調整済み/未調整の区別を出力に必ず併記し、株式分割・配当落ちの近傍（分割比率に一致する段差）を検知したら
`CORPORATE_ACTION` フラグを付ける。EDINET/EDGAR の抽出値は XBRL の単位属性（円/千円/百万円）と
連結・単体区分を必ず併記する。
| hermes-relay（既存） | ニュース・Xセンチメント（仮説の入口のみ） | 構築済み | 既存契約内 | 三次（必ずデータで裏取り） | ユーザー許可の上 Claude WebSearch |

設計原則: **一次（法定・政府）＞二次（市場データ）＞三次（ニュース/SNS）の格付けを
全出力に明記**し、三次情報単独では判断セクションに書けない（Q9）。

APIキーの置き場所（M-006 対応で明示）: ローカルは `~/.asset-research/.env`
（リポジトリ外・自分のPCのみ）。リモートセッションで使う場合は CCR 環境の環境変数に設定。
**どちらのリポジトリにもキーはコミットしない。** キーが漏れた場合は各サイトで再発行。

## 5. データ構造

### 5.1 データの置き場所（何がどこに、誰から見えるか）

| データ | 置き場所 | 見える範囲 |
|---|---|---|
| スキル・スクリプト・本設計書 | `claude-skills`（**public**） | 全世界。個人情報を含めない |
| IPS・ジャーナル・分析メモ・保有状況 | 新規 private リポジトリ `ryotaroh180105/invest-journal` | 本人＋招待したセッションのみ |
| APIキー | `~/.asset-research/.env` と CCR 環境変数 | 本人のみ。**両リポジトリに置かない** |
| 金額の絶対値 | invest-journal にも**書かない**（比率%のみ） | private でも漏洩時被害を限定する |

`invest-journal` 構成（確定値）:

```
invest-journal/
├── ips.md                  # 投資方針書（1枚）
├── journal/
│   └── J-NNN-<slug>.md     # 意思決定ジャーナル（1判断1ファイル）
├── memos/
│   └── YYYY-MM-DD-<slug>.md  # 分析メモ
├── reviews/
│   └── YYYY-MM.md          # 月次レビュー
└── README.md               # 運用手順・キー発行先URL一覧
```

### 5.2 数値の出典付与形式（全出力共通）

```markdown
実質GDP成長率（日本, 2026Q1）: +0.4%（前期比年率）
  [source: e-Stat series=XXXX, retrieved: 2026-07-11T19:00Z, tier: 一次]
```

取得失敗時: `値: 未検証（FETCH_FAILED: <理由>）`。推測値での補完を禁止する。

### 5.3 分析メモの固定8セクション（欠けたら保存拒否）

```markdown
# <テーマ> 分析メモ
---
date: / type: 業界|銘柄|マクロ|投信 / tickers: / tier_sources: [一次N件, 二次N件, 三次N件]
---
1. 問い（何を判断したいのか1文）
2. 事実（出典付き数値のみ。§5.2形式。三次情報はここに書けない。
   **数値がニュース/X（三次）由来の場合、fetcher で一次/二次から再取得できた値のみ記載可**。
   保存時に出典URLの実到達と、2ソース要件のドメイン独立性（同一配信元の複製は1ソース扱い）を機械検査する）
3. Bull case（強気仮説と、それを支える事実の番号）
4. Bear case（弱気仮説と、それを支える事実の番号）★空欄不可
5. 反証条件（何が観測されたら自分の見立てが間違いか。測定可能な形で）★空欄不可
6. ベンチマーク反実仮想（全世界インデックス積立と比べてこの行動が勝る理由）★空欄不可
7. コスト・税制（NISA枠/特定口座、信託報酬・手数料、想定税負担）
8. 結論と確信度（見送り/ウォッチ/ジャーナル登録へ。確信度 低|中|高 と根拠）
```

### 5.4 ジャーナル・スキーマ

```markdown
---
id: J-001
date: 2026-07-15
type: buy | sell | rebalance | watch
target: <銘柄/投信/資産クラス>
size_pct: <ポートフォリオ比%。金額は書かない>
thesis: <なぜ。分析メモへの相対リンク必須>
expected: <12ヶ月後に何が起きていると期待するか（測定可能に）>
falsifier: <これが起きたら撤退、の条件>
ips_check: pass | override(理由)   # §6.5 のゲート結果
review_date: 2027-01-15            # 原則6ヶ月後
status: open | closed
outcome: <クローズ時: 期待は当たったか・学び1行>
---
```

### 5.5 IPS（投資方針書）スキーマ

対話で埋める項目（確定リスト）: 運用目的と期間 / 月次入金可能額の有無（額は書かない）/
リスク許容度（最大許容ドローダウン% を自分の言葉で）/ 資産クラス配分レンジ
（例: 株式60±10%・債券/現金40±10%）/ 1銘柄の上限% / コア（インデックス積立）と
サテライト（個別）の比率上限 / NISA枠の使い方 / リバランス条件（レンジ逸脱時のみ）/
**変更ルール: IPS の変更は起案から7日後にのみ発効（暴落時の衝動改定を防ぐ）**。

## 6. 処理フロー

### 6.1 IPS 作成（初回1回）
入力: 対話回答 → 処理: §5.5 の全項目を1問ずつ確認、リスク許容度は「30%下落したら金額でいくら減るか」を提示して体感確認 → 出力: `ips.md`。

### 6.2 マクロダッシュボード
入力: なし → 処理: FRED/e-Stat から指標取得、各指標に過去10年レンジ内の現在位置（百分位）と3ヶ月方向を付与 → 出力: 表＋「今は歴史的にどういう局面か」の中立記述（売買推奨は書かない）。
**百分位はタイミングシグナルではない**: 百分位を根拠に現金比率を IPS レンジ外へ動かす提案をしない
（事実上の相場タイミング判断化を防ぐ。ダッシュボード末尾に固定文として明記する）。

### 6.3 分析（analyze <テーマ>）
入力: テーマ → 処理: (1) 該当データを fetcher で取得（Q1） (2) 必要なら biz-analysis / hermes-relay で定性材料（三次扱い） (3) §5.3 の8セクションを埋める。4・5・6が埋まらない場合はそのまま「保存不可: 反証が書けない=判断材料不足」と返す → 出力: `memos/` へ保存。

### 6.4 月次レビュー（30分に収める）
入力: journal/ と ips.md と現配分（ユーザーが%で申告） → 処理: (1) review_date 到来のジャーナルを列挙し答え合わせ (2) 配分の IPS レンジ逸脱を検出 (3) 的中/外れの傾向を3行で (4) 今月の override 回数・レビュー所要時間・システム保守に使った時間を記録 (5) invest-journal のコラボレーター一覧に想定外がないか確認 → 出力: `reviews/YYYY-MM.md` とリバランス**候補**（実行判断は人間）。

**縮退基準（IPSと同格・事前定義）**: レビュー所要60分超が2ヶ月連続、または fetcher 修繕が
月3件超 → Phase を1段階縮退する（価格系停止・マクロ＋ジャーナルのみ等）。拡張より継続を優先する。

### 6.5 ゲート（buy/sell 系のジャーナル登録前に必ず通る）
1. IPS 照合: 資産クラスレンジ・1銘柄上限・サテライト比率に収まるか。違反なら理由を書いて `override` 明記が必要
2. クーリングオフ: 初出テーマは登録から24時間後まで status を確定できない
3. FOMO チェック: 「直近1ヶ月で20%以上上昇したものか」「SNSで知ったか」に該当したら警告文を表示
4. ベンチマーク反実仮想（メモ §6欄）が空でないこと

### 6.6 暴落時モード（ユーザーが「下がってる」「売りたい」と言った時）
処理: 新規分析をせず、まず ips.md と該当ジャーナルの falsifier を表示し「反証条件に該当しているか」だけを判定する。該当なし→「IPS 上は何もしない日」と返す。該当あり→通常の 6.3 へ。

## 7. エッジケース

| ケース | 期待挙動 |
|---|---|
| APIキー未設定 | どのキーか・発行URL・置き場所を表示して停止（無言で失敗しない） |
| yfinance 破損（非公式ゆえ） | stooq へ自動フォールバック。両方失敗なら価格系機能のみ `FETCH_FAILED` で継続 |
| データが7日以上古い | 出力に `STALE` フラグを付け、判断セクションでの利用に警告 |
| ジャーナル review_date 超過が3件以上 | 新規 analyze の前にレビューを促す（記録だけ溜まる形骸化の防止） |
| invest-journal が無い/読めない | セットアップ手順（private repo 作成→セッションに add_repo）を提示して停止 |
| ユーザーが金額の絶対値を書こうとする | %への書き換えを提案（Q6・漏洩被害限定） |
| e-Stat/EDINET の応答遅延 | タイムアウト30秒、リトライ2回、以後 `FETCH_FAILED` |

## 8. 失敗シナリオとレッドチーム所見

| # | 失敗シナリオ | 早期警報サイン | 設計上の対策 |
|---|---|---|---|
| 1 | 規律装置が「面倒な儀式」化し、ゲートを飛ばして雑に使い始める（システムは動くが品質が死ぬ） | override が2回連続／メモの bear case が1行の形骸記述になる | ゲートは4項目・月次30分に最初から圧縮（Q10）。月次レビューに「今月 override 何回」を自動表示 |

## 11. 実装時判断ルール

- 指標の系列IDが取れない/廃止されていた → 代替系列を FRED 内で探し、コメントで新旧IDを残す。見つからなければその指標を `FETCH_FAILED` 扱いにして先へ進む（実装を止めない）
- yfinance の返す値が明らかに異常（前日比±50%等） → 値を出さず `SUSPECT_DATA` フラグ。silent に採用しない
- 「予測して」とユーザーに言われた場合の挙動 → 予測はせず、シナリオ別の既知の事実整理（金利が上がった場合に過去何が起きたか等、出典付き）に変換して返す、と SKILL.md に明記
- 日本語/英語ソースの数値が食い違う → 両方併記し tier の高い方を採用、相違を「未確認」節へ
- 迷ったら: 機能を足す方向ではなく、出力に出典と反証を足す方向に倒す
