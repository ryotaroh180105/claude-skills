# Fable 5 戦略的設計資産・作成対象一覧（超・完全網羅版）

Fable 5 の無料期間終了（2026-07-07）を見据え、設計能力を資産として凍結保存するための
作成対象マスタープラン。運用原則: **「実装させるな、設計させろ」**（Fable で設計、
Sonnet/Opus で実装・運用）。

このドキュメントは候補の集積であり、`ROADMAP.md` の「候補リスト」で採択判断してから
`repo-skill-creator` の手順で実装する。ここに載っているだけでは着手しない。

## 1. キャリア・コンサル業務成長戦略アセット

### 1.1 personal-growth-strategy-engine（成長戦略エンジン）

- 入力: 制作物（コード・資料）、フィードバックログ（松本氏等の指摘）、主な業務内容、
  所属企業情報（Sunnet、北海道ガス等）。
- コア機能:
  - 評価軸のズレ診断: 現場の期待（結論ファースト回避、データ根拠）と現状の乖離を分析し、
    評価を高める修正ポイントを言語化。
  - ROI可視化ロジック: 技術的成果を事業価値（コスト削減・利益率向上）に翻訳するレポート構成案。
  - ティア別アクション生成: 期限（7/7まで、7/8以降）と重要度に基づき、タスクをティアS
    （構造化・自動化）とティアA（戦略設計）に自動分類。
- 出力: 具体的かつ実行可能な「業務改善・評価最大化アクションリスト」。

### 1.2 コンサル業務向上スキル

クライアントの課題（Sunnet/北海道ガス等）に対し、論理的根拠とROIをビジネス言語で提示する
思考支援。

### 1.3 社内タスク管理改善案

現状のMTG運用アプリを分析し、より効率的な管理フローとアプリ変更案を策定・運用する。

### 1.4 エージェント開発・巻き取り補助

既存開発の進捗を高速キャッチアップし、開発をスムーズに引き継ぐためのサマリー生成
（他人／後任インターンへの引き継ぎを想定）。

## 2. 基盤システム・情報集約パイプライン

### 2.1 情報集約・リサーチエージェント（完成版）

- システムR/G統合: Web/note/X/Instagram の情報を正規化DBに集約し、検索可能にする。
- ブックマーク連携機能: 外部でブックマークした情報を即座に情報DBへ取り込むコネクタ。
- Kindle AI リサーチ・要約VPN: Kindle閲覧中に不明点を即座に調査し、内容を要約・DBへ蓄積する。
- 事実確認・トレンド調査の分担: 事実（法律・IR）は NotebookLM、トレンドは ChatGPT と使い分け、
  Fable には「プロンプト設計」のみをさせる。

### 2.2 分析系スキル

市場分析・競合分析・競合ボトルネック分析。

## 3. プロフェッショナル・アウトプットスキル群

### 3.1 document-foundation & 専門3スキル

- 基礎: 結論ファースト回避、事実確認、読者視点の徹底。
- `client-deliverable`: 意思決定者向けROI提案。
- `agent-spec`: 技術仕様・MCP接続・既知バグ記録。
- `manual`: 初心者・後任インターン向けマニュアル。

### 3.2 ハーネスセットアップマニュアルの研磨

IT初心者・次から入るインターンでも理解できるよう、図解や平易な言葉で説明を研磨する。

### 3.3 コードベース処理フロー可視化スキル

コードを読み込み、HTML図解やMarkdownで分かりやすい処理フロー図を自動生成する。

### 3.4 ボイスメモ・議事録エージェント

スマホのボイスメモ音声を一瞬で要約し、議事録・フィードバックとして整形するシステム
（既存の `voicememo-pipeline` スキルの拡張／別ユースケースとして検討）。

## 4. クリエイティブ・特定アプリ開発プロジェクト

### 4.1 高品質LP作成4ステップ・スキル（tatsuki式）

インテーク → デザイン言語化 → 一発生成 → セルフQA のフローで、手直しゼロの納品品質を
目指す（既存の `lp-builder` スキルとの統合を検討）。

### 4.2 特定アプリケーション開発

- コマtimes（KomaTimes）: 動作設計から実装までを一気通貫で行う。
- テニスアプリ: デプロイまでを完了させ、実運用に乗せる。
- 動画編集エージェント: FFmpeg と OpenMontage の思想を組み合わせ、AI判断×コード処理で
  高品質動画を生成する。

## 5. SNS運用・アフィリエイト・マネタイズ

### 5.1 アフィリエイト収益化構造の構築

TikTok, note, Twitter(X), Threads を連携させた収益化フローの設計。

### 5.2 OSS解説スキル（note用）

GitHubでバズっているOSSの仕様を、中級IT理解者向けに噛み砕いた解説記事として自動作成する。

### 5.3 変換ライン

長文1本から14本のSNSポストを量産し、`voice-profile-extractor` で個人の文体を維持する
（既存の `sns-ops-team` / `sns-auto-posting` との統合を検討）。

## 6. メタ管理・運用最適化（Fable資産の凍結保存）

### 6.1 skill-design-rigor（設計規律）と運用原則

原則: 「実装させるな、設計させろ」（Fableで設計、Sonnetで運用）。

### 6.2 Fable-Sonnet 運用ブリッジ

Fable の深い推論を Sonnet が理解可能な詳細な指示書へ変換するプロセス。

### 6.3 毎週のミス学習リフレクション

溜まった「今週のミス」を分析し、二度と起こらないよう自動でコードやルール（SKILL.md）へ
記載・更新する仕組み（既存の `MISTAKES.md` 運用ルールの週次バッチ化を検討）。

### 6.4 レポジトリ整理エージェント

ルール・スキル・アプリが混在するこのリポジトリを、運用ルールに基づき最適に整理・構造化する
（このリポジトリでは「運用ルール／スキル／作りたいアプリ」が同じリポジトリ内で管理されており、
分離したいという課題意識がある）。

### 6.5 マルチエージェント・チーム設計

- 役割分担: リーダー（Fable）、実行部隊（Sonnet/Codex）、批判的分析エージェント
  （反証・リスク指摘、攻撃者視点／ユーザー視点／経営視点の複数ペルソナ）。
- 採用フレームワーク:
  - Claude Agent Teams（Claude Code内蔵）: 対話的な分業（資料作成、開発）。
  - Claude Agent SDK（Pythonベース）: 定期無人稼働（SNS収集・分析）。
- ルール管理: `AGENT_TEAM.md` によるファイル所有権・共有ファイル変更の宣言プロトコル・
  オーケストレーター権限の定義。
- チーム構成例1（納品品質LP作成チーム）: ディレクター（Fable 5）/ デザイナー
  （Frontend Designスキル）/ コーダー（Sonnet 5・Codex 並列稼働）。
- チーム構成例2（SNS運用・資産化チーム）: リサーチャー（NotebookLM/ChatGPT）/
  アナリスト（システムG）/ ライター（voice-profile）。

## 種別分類（スキル化 / 常時ルール化 / アプリ化）

元リストには性質の異なる3種が混在していたため分離する。実装方式が違うため
（スキル=`plugins/`配下でオンデマンド発動、ルール=CLAUDE.mdに常時適用として記載、
アプリ=独立したコード成果物としてデプロイ）、混在させたまま設計すると手戻りが起きる。

### A. スキル化（`plugins/` にオンデマンド発動スキルとして実装）

- personal-growth-strategy-engine（1.1、コンサル業務向上スキル1.2を吸収）— 設計済み(01)
- 情報集約・リサーチエージェント（2.1: システムR/G統合、Kindle AIリサーチ、ブックマーク連携）— 設計済み(03)
- 分析系スキル（2.2: 市場・競合・ボトルネック分析）— 設計済み(05)
- アフィリエイト収益化構造（5.1、OSS解説note5.2・変換ライン5.3を含む）— 設計済み(06)
- エージェント開発・巻き取り補助（1.4）
- ハーネスセットアップマニュアルの研磨（3.2）
- コードベース処理フロー可視化スキル（3.3）
- ボイスメモ議事録エージェントの拡張（3.4、既存`voicememo-pipeline`の拡張）
- 高品質LP4ステップの統合（4.1、既存`lp-builder`との統合）
- レポジトリ整理エージェント（6.4、実行は一度きりでも手順はスキル化して再利用可能にする）— 設計済み(04)
- 社内タスク管理改善案（1.3、分析・提案書生成はスキル。実際のアプリ変更運用はアプリ化Cへ）

### B. 常時ルール化（CLAUDE.mdに常時適用として記載する原則・運用ルール）

- fable-operating-principles: 「実装させるな、設計させろ」原則
- 指示の密度: 察しの良さに甘えず言語化フェーズを必ず挟む
- effort運用: 設計=MAX、通常作業=高
- マルチエージェント運用時のファイル所有権・共有ファイル変更の宣言プロトコル
  （AGENT_TEAM.md、6.5）— ルール本体はB、エージェント定義ファイル自体はスキル/設定に近いためA相当の成果物も伴う
- 批判的分析エージェント（レッドチーム）を計画時に必ず通す原則（6.5）
- ルール・スキルの棚卸し運用（重複・矛盾の統合、旧版アーカイブ化）を定期的に行う原則

→ このカテゴリの設計は下記「設計書07」でOpusが担当。

### C. アプリ化（独立したコード成果物として実装・デプロイ）

- コマtimes（KomaTimes）
- テニスアプリ
- Kindle AI リサーチ・要約VPN（実体はブラウザ拡張／プロキシ的な補助ツール）
- 社内タスク管理MTGアプリの変更案そのもの（提案後の実装部分）
- 動画編集エージェント（FFmpeg+OpenMontage、CLIツールとしての成果物）
- ブックマーク→情報DB取り込みコネクタ（情報集約エージェントの一部だが独立デプロイが要る場合はこちら）

## 設計優先順位（Fable無料期間〜7/7 中に設計を終えるべき順）

判断基準: 「設計そのものの難易度が高く、Fableでないと構造化しにくいもの」を上位に、
「要件さえ固まればSonnetがそのまま実装設計まで含めてやれるもの」を下位に置く。
下位のものは無理にFableの時間を使わず、Sonnetセッションに直接渡してよい。

### Tier F（Fableで設計必須・優先度順）

1. **skill-design-rigor / Fable-Sonnet運用ブリッジ**（6.1, 6.2） — 他の全設計の土台。
   Fableの推論をSonnetが実装できる粒度に落とす変換フォーマット自体を先に決める必要がある。
2. **personal-growth-strategy-engine**（1.1） — 診断ロジック・ROI翻訳・ティア分類という
   3つの評価アルゴリズムの設計が核。曖昧な評価軸を構造化する部分がFableの強みが最も活きる。
3. **マルチエージェント・チーム設計**（6.5） — 役割分担・ファイル所有権・権限プロトコル
   （AGENT_TEAM.md）はアーキテクチャ判断そのもので、後から直しにくい。
4. **情報集約・リサーチエージェント（システムR/G統合）**（2.1） — 正規化スキーマ・
   矛盾検出・複数ソース（Web/note/X/Instagram/Kindle/ブックマーク）の統合設計は難度が高い。
5. **レポジトリ整理エージェント**（6.4） — 「ルール／スキル／作りたいアプリ」の分類軸
   自体の設計判断が必要（自分のリポジトリの構造決定なので後戻りコストが高い）。
6. **分析系スキル（市場・競合・ボトルネック分析）**（2.2） — 分析フレームワークの
   設計が肝で、テンプレ化には構造化思考が要る。
7. **アフィリエイト収益化構造**（5.1） — 複数プラットフォームを跨ぐ収益構造とKPI設計。

### Tier S（要件定義後はSonnetに任せてよい）

- コンサル業務向上スキル（1.2）— 1.1のテンプレ流用で十分。
- 社内タスク管理改善案（1.3）— 現状分析＋提案書。`document-creation`スキルで対応可能。
- エージェント開発・巻き取り補助（1.4）— 要約生成タスク。既存スキルの組み合わせで足りる。
- コードベース処理フロー可視化スキル（3.3）— 入出力が明確なツール。
- ハーネスセットアップマニュアルの研磨（3.2）— ライティングタスク。
- ボイスメモ議事録エージェント拡張（3.4）— 既存`voicememo-pipeline`の拡張のみ。
- 高品質LP4ステップの統合（4.1）— 既存`lp-builder`との統合のみ。
- コマtimes / テニスアプリ（4.2）— 個別アプリ要件定義＋実装。`requirements-definition`→Sonnet実装で回る。
- 動画編集エージェント（4.2）— FFmpegパイプラインは実装難度が高いが「設計」自体は既存OSS思想の踏襲で足りる。
- OSS解説note用スキル（5.2）— `owned-media`/`article-writer`の型を流用可能。
- 変換ライン（5.3）— 既存`sns-ops-team`/`sns-auto-posting`の延長。
- 毎週のミス学習リフレクション自動化（6.3）— `loop-engineering`スキルで自動化設計すれば足りる。
