### 2.10 AI臭を消すプロンプト8選

1. **編集長モード**: プロの編集者としてこの文章を会話調に直してください。AIっぽい言い回しや硬い構成をなくし、意味はそのまま残してください。
2. **人間らしさ復元**: 経験のある人が書いたように、文章のリズムと言葉選びを改善してください。AI特有の型や定型表現は避けてください。

## 3. 設計知識・原則（ドキュメント/CLAUDE.md 反映候補）

### 3.1 Skills vs SubAgents 判断チェックリスト（KAWAI @kawai_design）

- **Skillsは手順、SubAgentsは役割**。初心者はSkillsから
- 判断フロー: ①毎回同じ手順？ ②成果物が決まっている？ ③1人で処理可能？ ④複数視点が必要？ → ①〜③はい＆④いいえ → Skills / それ以外 → SubAgents
- Skillsが向く: 記事企画・議事録整理・調査要約・レビュー前チェック（成果物が固定、手順に従えば誰でも同品質、判断の自由度が低い）
- SubAgentsが向く: 実装とレビュー分離 / 調査と戦略分離 / 安全確認 / デザインレビュー（役割例: 調査担当・レビュー担当・実装担当・安全確認担当）
- 作る順番: CLAUDE.md → article-planner → meeting-summary → research-brief → 必要ならSubAgents
- → 📝 repo-skill-creator の判断基準節に追加

### 3.2 生成AIの構造的な強み・弱み（もとやま @ysk_motoyama）

- 仕組み: 「次に来る確率が最も高い単語を選ぶ」の繰り返し。特徴①相関で動く（因果はわからない）②一方通行（見直し工程がない）③学習データと指示に引っ張られる（追従性: 「答えはXだと思う」と添えるだけで誤答への同調率63.7%）
- 強み: ①ふわっとした指示を明確に言語化 ②自分にない観点を広げる（明示的に「反対意見を」「見落としは」と要求すると最大化）
- 弱み: ①もっともらしさ≠正しさ（ハルシネーションは構造的必然）②因果は語れない（因果仮説は人間が与える）③構造化・MECEが苦手（構造の指定は人間の仕事）
- **Epistemia（エピステミア）**: 「文章がもっともらしいから正しいに違いない」と人間が妥当性評価をサボる現象。妥当性の評価は人間がやる
- → 📝 CLAUDE.md または work-approach-playbook に「AI出力の検収原則」として反映

### 3.3 65行CLAUDE.md の4原則（GitHub Trending 1位 28日維持と主張される投稿）

1. 書く前に考える（前提を勝手に決めず、迷ったら聞く）
2. シンプルさ最優先（最小限のコードで解決。余計な推測をしない）
3. 外科手術のように変更する（必要な場所だけ触る。隣接コードは触らない）
4. 成功基準で動く（何をもって完了かを先に定義し、検証できるまで進める）

→ 📝 既存の yagni-guard と重複大。差分（成功基準の事前定義）のみ CLAUDE.md に反映
