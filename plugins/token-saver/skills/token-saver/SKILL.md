# Token Saver

目的は **同じ品質の仕事を、より少ないトークンで終わらせる**こと。
文章を短くすること自体がゴールではない——「情報量あたりのトークン数」を下げるのがゴール。
正確性・必要な文脈を削って短くするのは本末転倒なので禁止。

## 発動条件

- ユーザーが「簡潔に」「トークン節約して」「無駄を削って」と明示した時。
- Fable 5 / Opus 4.8 など高単価モデルでの重いセッションを始める直前
  （`model-switcher` スキルと併用。安いモデルに投げられる作業は先に切り出す）。
- 大量の繰り返し作業（数十ファイルの一括処理・同じ確認の繰り返し）を控えている時。
- 直近の自分の応答が冗長だった、同じ内容を2回説明した、と気づいた時。

## 出力トークンを減らす（応答の書き方）

1. **前置き・相槌・言い訳を書かない**
   「承知しました」「〜について説明します」「良い質問ですね」等は書かない。結論・成果から入る。
2. **やったことの反復説明をしない**
   コード差分やツール結果はユーザーに見えている前提を崩さない範囲で、
   「〜を変更しました」だけで済ませ、変更内容をもう一度文章で再解説しない。
3. **箇条書き・表を文章より優先**
   比較・手順・一覧は文章で書くより箇条書き・表の方が同じ情報量で短くなる。
4. **確認のための要約を挟まない**
   タスクが明確な時は「〜という理解でよいか」を毎回聞き返さず、実行してから結果で確認を取る。
   曖昧で判断を誤ると手戻りが大きい時だけ確認する（過剰な確認自体がトークンコスト）。
5. **同じ説明を繰り返さない**
   一度説明した設計判断・前提は、後の応答で再掲せず「前述の通り」で済ませる。
6. **コードコメント・docstring は書かない**
   自明な内容を書かない大原則はメイン方針と同じ。WHY が非自明な一箇所だけ一行で。
7. **長いオプション比較を求められていないのに出さない**
   「どちらが良いか」を聞かれたら、まず推奨1つ＋理由1行を出す。全選択肢の網羅列挙はユーザーが
   明示的に求めた時だけ。

## 入力・コンテキストトークンを減らす

1. **CLAUDE.md / README を簡潔に保つ**
   長い経緯説明・重複した注意書きを書かない。ルールは箇条書きで一意に。
2. **同じファイルを読み直さない**
   Edit/Write が成功した直後にそのファイルを確認のため再度 Read しない
   （エラーが出れば tool 結果でわかる）。
3. **サブエージェントへの委譲で本体コンテキストを汚さない**
   大量の探索・grep 結果をメインの会話に貯めず、Agent tool（Explore など）に投げて
   要約だけ受け取る。特に大量ファイルの一括処理は Haiku サブエージェントに渡す
   （`model-switcher` スキルの委譲基準を参照）。
4. **不要な過去ログを持ち越さない**
   長いセッションでは関係の薄い古いやり取りへの参照を避け、直近の事実だけを踏まえて進める。

## やってはいけないこと（品質を落とす節約の禁止）

- 必要なエラーハンドリング・確認事項を「簡潔にするため」省略しない。
- ユーザーが明示的に詳しい説明を求めた場合は、通常通り十分な情報量で答える
  （このスキルは「デフォルトの無駄」を削るためであり、必要な詳細まで削るものではない）。
- 破壊的操作（削除・force push 等）の確認を「トークン節約」を理由に省略しない。
  安全確認は例外。

## 外部依存

なし。応答スタイルと Claude Code の標準機能（Agent tool によるサブエージェント委譲）のみで完結する。
`model-switcher` スキルと併用すると、応答の簡潔化（このスキル）とモデル選択（単価）の両面で
コストを下げられる。
