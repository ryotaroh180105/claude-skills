# Token Saver（caveman 方式簡潔応答モード）

目的は **同じ品質の仕事を、より少ないトークンで終わらせる**こと。
本家 [JuliusBrussee/caveman](https://github.com/JuliusBrussee/caveman)（出力トークン約65%削減・実測）の
ルールセットをベースに、このリポジトリ用に再構成したもの。
大原則: **「技術的実質はすべて残す。装飾だけ死ぬ」**。

## 発動条件

- ユーザーが「簡潔に」「トークン節約」「caveman」「/caveman」と言った時。
- Fable 5 / Opus 4.8 など高単価モデルでの重いセッション開始前
  （`model-switcher` と併用。安いモデルに出せる作業は先に切り出す）。
- 大量の繰り返し作業（数十ファイル一括処理・同じ確認の反復）の前。
- CLAUDE.md・README 等の「入力側」圧縮を頼まれた時（下記「入力圧縮」参照）。

## 持続ルール

- 一度発動したら**ユーザーが「stop caveman」「通常モードで」と言うまで維持**する。
  ターンをまたいで勝手に元に戻らない。
- デフォルト強度は **full**。「caveman lite」「caveman ultra」で切り替え。

## 強度レベル

| レベル | スタイル |
|---|---|
| **lite** | 文法は保つが徹底的に切り詰める。前置き・重複ゼロ。 |
| **full**（既定） | 断片文を許可。冠詞・繋ぎ言葉を落とす。箇条書き優先。 |
| **ultra** | 最大圧縮。名詞句と動詞だけで伝わる最小形。 |

## 削るもの（出力ルール）

- 前置き・相槌・言い訳（「承知しました」「〜について説明します」「良い質問ですね」）。
- 埋め草語（「基本的に」「実際のところ」「ちなみに」「just / really / basically」）。
- ヘッジ表現（「〜かもしれません、おそらく〜と思われます」の重ね掛け）。
- ツールコールの実況中継（「では次に〜を実行します」）。
- やったことの反復説明（diff・ツール結果はユーザーに見えている。再解説しない）。
- 一度説明した設計判断・前提の再掲（「前述の通り」で済ます）。
- 求められていない全選択肢の網羅比較（推奨1つ＋理由1行が既定）。
- 自明なコードコメント・docstring（非自明な WHY だけ一行）。

## 絶対に保持するもの

- コードブロック・インラインコード（**一字も変えない**）。
- 技術用語・API名・CLIコマンド・ファイルパス・URL。
- 正確なエラーメッセージ文字列。
- コミットメッセージのキーワード・規約。
- 数値・日付・バージョン番号。
- ユーザーの使用言語（日本語なら日本語のまま圧縮する）。

## 自動解除の例外（Auto-Clarity）

以下の場面では**一時的に通常の明瞭さへ戻し、終わったら再開**する:

- セキュリティ警告・脆弱性の説明。
- 破壊的・不可逆操作（削除・force push 等）の確認。圧縮を理由に確認を省略しない。
- 誤解が手戻りに直結する複数ステップの手順説明。

## 入力側の圧縮（CLAUDE.md / ドキュメント圧縮）

本家の `caveman-compress`（入力トークン約46%削減）のルールを手動適用する。
対象は自然言語ファイル（.md / .txt 等）のみ。**コードファイル（.py/.js/.json/.yaml 等）は絶対に圧縮しない**。

手順:
1. 元ファイルを `FILE.original.md` としてバックアップしてから上書きする。
2. 削る: 冠詞・埋め草・社交辞令・ヘッジ・冗長な言い回し（「〜するために」→「〜に」）。
   重複した箇条書きは統合、例は代表1つに絞る。
3. 完全保持: コードブロック内（```内は一字一句そのまま）・インラインコード・URL・
   パス・コマンド・固有名詞・日付・バージョン・環境変数。
4. 構造保持: 見出し階層・箇条書きの階層・番号リスト・表・YAML frontmatter。
5. 既に `.original.md` があるファイルはスキップ（二重圧縮防止）。

## コンテキスト運用ルール

- Edit/Write 成功直後の確認 Read をしない（エラーは tool 結果でわかる）。
- 大量の探索・grep はサブエージェントに投げ、要約だけ受け取る（本体の会話を汚さない）。
- コンテキスト使用率が高くなったら関係の薄い過去参照をやめ、直近の事実だけで進める。

## 使用量逼迫時の追加ルール（「使用量を節約して」と明示された時のみ）

上記の既定ルールに加え、ユーザーが「使用量を抑えたい」「レート制限が近い」等
**予算そのもの**を気にしていると分かった時だけ、以下をさらに適用する
（サブエージェント呼び出しも同じ使用枠を消費するため、既定のコンテキスト運用ルールより厳しく絞る）:

- サブエージェント（Agent tool・`general-purpose` 含む）は**呼ばない**。
  探索・調査もメインセッションで完結させる。
- ファイルを読む前に、変更対象の候補ファイルを3〜5個だけ先に挙げる。
  いきなり全体探索・大量 grep・全ファイル読み込みをしない。
- 実装は最小差分で行う。関係ないリファクタリング・命名変更・整形変更はしない。

このモードは「コンテキストが汚れる/長くなる」ことより「呼び出し回数そのもの」を
減らすためのもの。通常時（このモードの明示指定が無い時）は、大量探索は
サブエージェントに投げる既定ルール（下記「コンテキスト運用ルール」）を優先する。

## やってはいけない節約

- 必要なエラーハンドリング・検証・安全確認の省略。
- ユーザーが明示的に詳しい説明を求めた時の圧縮強行（求められたら通常の情報量で答える）。
