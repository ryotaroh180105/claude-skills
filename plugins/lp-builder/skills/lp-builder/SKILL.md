# LP Builder — LP制作の副業ワークフロー

LP制作案件を「ヒアリング → 構成設計 → コピー → 実装 → デプロイ → 修正対応」の
6工程で進めるためのスキル。成果物は**単一HTMLファイル**（CSS/JSインライン）を基本とし、
どのサーバーでも動く・納品が軽い・修正差分が追いやすい状態を保つ。

## いつ使うか

- 副業・クライアントワークで新規LPを制作するとき（見積もり・提案段階を含む）
- 既存LPの改善（CV率向上のための構成・コピー・導線の見直し）を頼まれたとき
- 納品後の修正依頼に対応するとき
- 自分のサービスやポートフォリオのLPを作るとき（自分自身をクライアントとして扱う）

## 工程1: ヒアリング

`templates/hearing-sheet.md` をクライアントに渡す（または対話で埋める）。
★印の5項目（商材/ターゲット/CV定義/訴求ポイント/納期・予算）が最低ライン。

- **CV定義を最初に固める**。問い合わせ・購入・登録のどれかでLPの構成もフォーム選定も変わる。
  曖昧なら「LPを見た人に最終的に何をしてほしいですか？」と一点だけ必ず聞く。
- 自分のサービスのLPを作る場合も同じシートを自分で埋める。書けない欄＝商品設計の弱点。
- **情報が少ないまま初回提案する場合**: ヒアリングを待たずに、公開情報（既存サイト・SNS）から
  シートを仮埋めして「仮説ドラフト＋確認したい質問リスト」をセットで出す。
  仮置きした箇所は `【仮】` を付けて明示し、提案の場で潰す。

## 工程2: 構成設計 — 型の使い分け

| 型 | 流れ | 向いている商材 |
|---|---|---|
| AIDA | 注目→興味→欲求→行動 | 認知が浅い新商品・イベント集客 |
| PASONA | 問題→煽り・共感→解決策→提案→絞込→行動 | 悩み解決型（美容・学習・BtoBサービス） |
| BEAF | ベネフィット→実績・証拠→優位性→特徴 | 比較検討されるEC商品・料金勝負の商材 |

迷ったら PASONA を基本とし、以下の標準セクション構成に落とす。

1. **ファーストビュー**: キャッチコピー＋サブコピー＋CVボタン。3秒で「誰の何が解決するか」が伝わること
2. **課題共感**: ターゲットの悩みを「あるある」として言語化（3つ前後の箇条書き）
3. **ベネフィット**: 機能ではなく変化後の姿を書く（「高速」ではなく「待ち時間ゼロで◯◯できる」）
4. **社会的証明**: 実績数字・お客様の声・メディア掲載。捏造は不可、無ければセクションごと削る
5. **サービス詳細**: 提供内容・流れ・写真。ここで初めてスペックを語ってよい
6. **料金**: 迷わせない見せ方（推奨プランを視覚的に強調）。価格を出せない案件は「見積もり無料」をCVに
7. **FAQ**: 購入をためらう理由を先回りして潰す（5問前後）
8. **クロージングCTA**: ベネフィット再提示＋CVボタン＋不安の最終除去（保証・キャンセルポリシー）

### 既存LPの改善の場合

新規制作ではなく改善依頼のときは、現行LPを上の標準8セクションと照らして診断してから工程を選ぶ。
①CVボタン（文言が動詞か・モバイルで常時見えるか）②ファーストビュー（3秒で価値が伝わるか）
③社会的証明の有無 ④スマホ表示崩れ、の順に確認し、指摘を「影響大→小」で一覧化して提案する。
構成ごと作り直すなら工程2から、コピー・導線の手直しなら工程3・5だけを使えばよい。

### コピーライティング指針

- キャッチコピーは「ターゲット＋ベネフィット＋数字or具体性」で3案以上出してクライアントに選ばせる
- 1セクション1メッセージ。詰め込みたくなったらセクションを分ける
- CVボタンの文言は動詞で（「送信」ではなく「無料で相談してみる」）。全ボタン同一文言・同一色
- 美容・健康・金融系は薬機法・景表法に触れる断定表現（「必ず痩せる」等）を避け、必要なら要確認と明示

## 工程3: 実装 — 技術指針

**単一HTML・レスポンシブ・軽量**の3原則。フレームワーク・ビルドツール・外部CSSは使わない。

- モバイルファーストで書き、`min-width` のメディアクエリでPCに広げる
- CVボタンはモバイルで画面下部に固定表示（`position: fixed`）。フッター付近では重なりに注意
- OGP・メタ情報（`og:title` / `og:image` / `description`）を必ず入れる。SNS共有時の見た目が営業になる
- 画像は `loading="lazy"`（ファーストビューの画像だけ除外）、`width`/`height` 指定でレイアウトシフト防止
- フォームは自前実装しない。選択肢を提示して選んでもらう:
  - **Google Forms 埋め込み**（無料・最速。デザイン統一は弱い）
  - **Formspree 等のフォームサービス**（HTMLフォームのまま使え、デザイン統一可。無料枠に送信数制限）
  - **LINE公式/予約サービスへのリンク**（CVがLINE登録・予約の場合はこれが最短）

### 雛形構造（セクション構成のHTMLアウトライン）

```html
<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>【サービス名】 | 【キャッチコピー】</title>
  <meta name="description" content="【120字以内の説明】">
  <meta property="og:title" content="【サービス名】">
  <meta property="og:description" content="【説明】">
  <meta property="og:image" content="【公開URL/ogp.png】">
  <style>/* CSSはすべてここにインライン。モバイルファースト */</style>
</head>
<body>
  <header class="hero">
    <h1>【キャッチコピー】</h1>
    <p>【サブコピー】</p>
    <a class="cta" href="#contact">【CVボタン文言】</a>
  </header>
  <section class="problem"><h2>こんなお悩みありませんか</h2><ul><li>【悩み】</li></ul></section>
  <section class="benefit"><h2>【ベネフィット見出し】</h2></section>
  <section class="proof"><h2>実績・お客様の声</h2></section>
  <section class="detail"><h2>サービス内容</h2></section>
  <section class="pricing"><h2>料金</h2></section>
  <section class="faq"><h2>よくあるご質問</h2></section>
  <section class="closing" id="contact">
    <h2>【クロージング見出し】</h2>
    <!-- Google Forms iframe / Formspree の form / LINEリンク のいずれか -->
    <a class="cta" href="【フォームURL】">【CVボタン文言】</a>
  </section>
  <footer><small>© 【年】 【事業者名】 | 特定商取引法に基づく表記（物販の場合）</small></footer>
  <a class="cta cta-fixed" href="#contact">【CVボタン文言】</a>
  <script>/* JSもインライン。スムーススクロール程度に留める */</script>
</body>
</html>
```

実装後は必ず: ブラウザ幅 375px / 768px / 1280px で表示確認、CVボタンの動作確認、
HTMLの構文チェック（タグの閉じ忘れ）を行ってから初稿を提出する。

## 工程4: デプロイ — 無料枠での公開

クライアント指定が無ければ以下から選ぶ。**アカウントは案件ごとにクライアント側で用意してもらう**
（自分のアカウントで公開すると納品後の移管・解約でもめる）。

```bash
# Vercel（推奨: 最速。index.html があるディレクトリで）
npx vercel --prod

# Netlify
npx netlify-cli deploy --prod --dir=.

# GitHub Pages（リポジトリ運用したい場合）
git init && git add index.html && git commit -m "publish lp"
gh repo create <repo-name> --public --source=. --push
gh api repos/{owner}/{repo}/pages -X POST -f "source[branch]=main" -f "source[path]=/"
```

- 独自ドメイン: 各サービスの管理画面でドメインを追加 → クライアントのDNSに
  CNAME（サブドメイン）または A/ALIAS レコード（apex）を設定してもらう。
  DNS変更はクライアント側作業なので、手順書を渡して反映まで最大48時間かかる旨を伝える
- 公開後チェック: 実機スマホ表示 / OGPプレビュー / フォームのテスト送信（自分宛て）を必ず行う

## 工程5: 修正対応の型

受け方の基本は work-approach-playbook スキルに従う。LP案件固有のポイント:

- **契約時に合意しておく**: 修正回数（標準2回）と範囲。「文言・画像差し替え・色調整」は修正、
  「セクション追加・構成変更・CV定義の変更」は仕様変更として別見積もり
- 修正依頼は口頭で受けず、箇条書きで書面化して認識合わせしてから着手する
- 修正のたびに `index_v2.html` のような複製は作らず、1ファイルを更新して変更点リストを添えて再納品
- 公開済みLPの修正は、修正版をプレビューURL（Vercel等のプレビューデプロイ）で確認してもらってから本番反映

## エッジケースの扱い

- **素材（画像・ロゴ）が無い**: 制作を止めない。ロゴはテキストロゴ、画像はCSSグラデーション背景
  またはフリー素材（Unsplash等・商用可を確認）で先行実装し、`【要差し替え: ◯◯の写真】` と
  コメントで印を付けて納品前に一覧をクライアントに渡す
- **ターゲットが不明**: 「誰にでも刺さるLP」は作れないと伝えた上で、商材から最有力ペルソナを
  1つ仮定して制作し、仮定を明記して提出。「全員向け」の要望には主ターゲット1＋サブ訴求1までに絞る
- **納期が極端に短い（当日〜翌日）**: 最小構成（ファーストビュー＋ベネフィット＋CVフォームの
  3セクション）で公開を優先し、残りセクションは公開後に追記する2段階納品を提案する。
  その場合も CV導線とスマホ表示確認だけは省略しない

## 前提セットアップ

外部依存なし。このスキル自体はAPIキー・MCP不要で動く。

| 項目 | 必要になる場面 | 用意する人 |
|---|---|---|
| Vercel / Netlify / GitHub アカウント | 工程4のデプロイ時のみ | クライアント（案件ごと） |
| 独自ドメイン | 独自ドメイン公開時のみ | クライアント |
| フォームサービス（Google Forms / Formspree） | フォーム設置時 | クライアント名義を推奨 |

デプロイ先が未定のままでも工程1〜3は完了できる。納品形態が「HTMLファイル渡し」なら工程4は不要。
