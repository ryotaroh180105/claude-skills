# AWS Exam Practice — AWS 認定試験 模試スキル

AWS 認定試験の学習を「出題 → 採点 → 解説 → ログ記録 → 弱点復習」のサイクルで支援する。
デフォルトは SAA-C03（Solutions Architect Associate）。CLF（Cloud Practitioner）など
他の試験種別も、ユーザーが指定すればドメイン配分を差し替えて同じ流れで対応する。

## 重要な注意書き（セッション冒頭で必ず伝える）

- 出題する問題はすべて **Claude が生成するオリジナル問題**であり、実際の試験問題の転載ではない。出題傾向・難易度は公式試験ガイドに沿って再現するが、本番と同一の問題は出ない。
- Claude の知識にはカットオフがあり、**最新のサービスアップデート（新機能・料金改定・新サービス）が反映されていない可能性がある**。本番直前には AWS 公式のサンプル問題・AWS Skill Builder の公式模試も必ず併用するよう案内する。

## 前提セットアップ

外部依存なし。API キー・MCP 不要。学習ログはカレントディレクトリの `aws-study-log.md` に保存する。

## 開始時のフロー

1. **試験種別の確認**: ユーザーが指定しなければ「SAA-C03 前提で出題します（CLF など別試験なら指定してください）」と一言添えて SAA で開始する。逐一の確認で手を止めない。
2. **学習ログの確認**: カレントディレクトリに `aws-study-log.md` があるか確認する。
   - **無い場合（初回）**: 復習モードは選べない。依頼文でモードが明確なら（「模試やりたい」等）そのまま開始し、「初回なので 10 問のレベル確認から始める手もあります」と一言添えるだけに留める。モードが曖昧なときだけレベル確認を第一候補として提案する。初回セッション終了時にログファイルを新規作成する。
   - **ある場合**: 前回の弱点サマリーを 2〜3 行で振り返ってからモードを提案する（例:「前回は コスト最適化 55%、弱点タグは S3 / VPC。復習モードにしますか？」）。
3. **モード選択**: 以下から選ぶ。ユーザーの依頼文で明らかな場合（「65問フルで」「1問ずつ解説して」等）は確認せず開始する。

| モード | 問題数（既定） | 解説タイミング | 用途 |
|---|---|---|---|
| 模試モード（デフォルト） | 65問 | 最後にまとめて | 本番シミュレーション |
| 演習モード | 10問 | 1問ごとに即時 | 日々の学習・分野指定演習 |
| 復習モード | 10問 | 1問ごとに即時 | ログの弱点タグから出題 |
| レベル確認 | 10問 | 最後にまとめて | 初回の現在地測定 |

問題数はユーザー指定があればそれに従う（「模試を20問だけ」等も可）。

## 出題ルール（全モード共通）

- **形式**: 本番同様のシナリオ型。「ある企業が〜を要件としている。最も◯◯な構成はどれか」の形で、要件（コスト/可用性/性能/セキュリティ/運用負荷）を明示する。
- **選択肢**: 単一選択（4択）を基本とし、65問模試では 5〜8 問程度を複数選択（5択から2つ選ぶ、問題文に「2つ選べ」と明記）にする。
- **誤答選択肢の質**: 「明らかにありえない選択肢」を作らない。誤答は「別の要件なら正解になる」もっともらしい構成にする（後述のサンプル問題が品質基準）。
- **SAA-C03 のドメイン配分**（模試・レベル確認はこの比率で出題）:

| ドメイン | 配分 | 65問中の目安 |
|---|---|---|
| セキュアなアーキテクチャの設計 | 30% | 20問 |
| 弾力性に優れたアーキテクチャの設計 | 26% | 17問 |
| 高パフォーマンスなアーキテクチャの設計 | 24% | 16問 |
| コストを最適化したアーキテクチャの設計 | 20% | 12問 |

- **頻出テーマ**: S3 ストレージクラスとライフサイクル / EC2 vs Lambda vs ECS・Fargate / RDS vs DynamoDB vs Aurora / VPC 設計（サブネット・NAT・エンドポイント）/ IAM ポリシーとロール / ELB と Auto Scaling / CloudFront・Route 53 / SQS・SNS によるデカップリング / KMS・Secrets Manager / Well-Architected Framework。
- **分野指定演習**: 「コスト最適化だけ」「S3 の問題だけ」のようにドメインまたはサービスを指定されたら、配分を無視してそのテーマに集中する。
- CLF を指定された場合は CLF-C02 のドメイン（クラウドのコンセプト 24% / セキュリティとコンプライアンス 30% / テクノロジーとサービス 34% / 請求・料金・サポート 12%）に差し替え、シナリオの深さもアソシエイトより浅い知識確認寄りに調整する。

## 模試モードの進行

1. 問題は **5問ずつ**提示する（65問を一度に出すと読みにくく、1問ずつだとテンポが悪い）。
2. 回答は「1-B, 2-A, 3-D, 4-C, 5-B」のようにまとめて受け取る。次の5問へ進む。
3. **途中で正誤・解説は一切言わない**。相槌も「回答を記録しました。次の5問です」に留める（本番の緊張感を再現するため）。
4. 全問終了後に採点し、下記フォーマットでレポートする。

### 中断と再開

- ユーザーが中断を申し出たら（または応答が途切れて別の話題になったら）、その時点の進行状況（試験種別 / 消化数と回答 / 残り問題数）を `aws-study-log.md` の「進行中の模試」セクションに保存する。
- **同一セッション内の再開**: 出題済みの問題文が会話に残っているため、続きの問題から完全に再開できる。
- **別セッションでの再開**: 未出題分の問題文は復元できないため、「消化済み N 問のスコアは引き継ぎ、残り M 問は新規生成で続行」と正直に伝えて再開する。中断分を破棄して最初からやり直す選択肢も提示する。
- 模試完了時に「進行中の模試」セクションは削除する。

## 採点とレポート（模試・レベル確認の終了時）

```
## 採点結果: 48/65 (74%)  — 合格ライン目安: 72% (720/1000)
| ドメイン | 正答率 |
|---|---|
| セキュアなアーキテクチャ | 15/20 (75%) |
| 弾力性のあるアーキテクチャ | 12/17 (71%) |
| 高パフォーマンス | 13/16 (81%) |
| コスト最適化 | 8/12 (67%) |
```

続けて**間違えた問題のみ**を1問ずつ解説する。解説は毎回この3点セットで行う:

1. **なぜ正解が正解か**（要件のどのキーワードが決め手か。例:「12時間以内の取り出し」「運用負荷を最小化」）
2. **なぜ各誤答が誤りか + どんな場面なら正解になるか**（誤答を「使いどころ」として学び直せるようにする。これがこのスキルの解説品質の核）
3. **関連する Well-Architected の柱**（セキュリティ / 信頼性 / パフォーマンス効率 / コスト最適化 / 運用上の優秀性 / 持続可能性のどれに対応する論点か）

演習・復習モードでは、正解でも上記 2 を簡潔に添える（正解した問題こそ誤答の使いどころを学ぶチャンス）。

## 出題サンプル（この品質を基準にする）

**サンプル1（単一選択 / コスト最適化）**

> ある企業は、監査要件により 7 年間の保持が義務付けられたログファイルを S3 に保存している。ログは最初の 30 日間は分析のため頻繁にアクセスされるが、その後はほぼアクセスされず、監査の際に 5 時間以内に取り出せればよい。**最もコスト効率が良い**構成はどれか。
>
> - A. S3 Standard に 7 年間保存し続ける
> - B. 30 日後に S3 Glacier Flexible Retrieval へ移行するライフサイクルルールを設定する
> - C. 30 日後に S3 Glacier Deep Archive へ移行するライフサイクルルールを設定する
> - D. 30 日後に S3 One Zone-IA へ移行するライフサイクルルールを設定する

**正解: B。** 「ほぼアクセスしない + 5 時間以内の取り出し」が決め手。Glacier Flexible Retrieval の標準取り出しは 3〜5 時間で要件を満たし、ストレージ単価は Standard の約 1/6。
- **C が誤りの理由**: Deep Archive はさらに安いが、標準取り出しに約 12 時間かかり「5 時間以内」を満たさない。→ 取り出し要件が「12〜48 時間で可」なら C が最適解になる。
- **A が誤りの理由**: 要件は満たすが、アクセスしないデータに Standard 料金を 7 年払うのは最もコスト効率が悪い。
- **D が誤りの理由**: One Zone-IA は 1 AZ 保存で AZ 障害時にデータ消失リスクがあり、監査必須データに不適。単価も Glacier より高い。→ 「再生成可能なデータのミリ秒アクセスを安く」なら D が正解候補になる。
- **Well-Architected**: コスト最適化の柱（需要に合ったストレージ階層の選択）。

**サンプル2（複数選択 / 弾力性）**

> ある企業の Web アプリケーションは、単一アベイラビリティゾーン（AZ）の EC2 インスタンス 1 台で稼働しており、データベース（MySQL）も同じインスタンス上にある。AZ 障害に耐えられるアーキテクチャにするために行うべきことを **2 つ**選べ。
>
> - A. EC2 を複数 AZ にまたがる Auto Scaling グループに配置し、ALB の背後に置く
> - B. MySQL を Amazon RDS の Multi-AZ 配置に移行する
> - C. EC2 のインスタンスタイプをより大きいサイズに変更する
> - D. 同一 AZ 内に MySQL のリードレプリカを追加する
> - E. CloudFront ディストリビューションをアプリケーションの前段に配置する

**正解: A, B。** アプリ層（A）とデータ層（B）の両方を複数 AZ 化して初めて AZ 障害に耐えられる。片方だけでは単一障害点が残る。
- **C が誤りの理由**: スケールアップは性能対策であり、1 台・1 AZ である限り可用性は変わらない。→ 「CPU 不足でレスポンスが遅い」問題なら正解候補になる。
- **D が誤りの理由**: 同一 AZ 内のレプリカは AZ 障害で共倒れになる。→ 「読み取り負荷の分散」が要件で、かつ別 AZ に置くなら有効な選択肢。
- **E が誤りの理由**: CloudFront はキャッシュ配信と遅延改善の手段で、オリジン（EC2/DB）が落ちれば動的処理は継続できない。→ 「グローバルユーザーへの静的コンテンツ配信を高速化」なら正解になる。
- **Well-Architected**: 信頼性の柱（単一障害点の排除、AZ を跨いだ水平スケール）。

## 学習ログ（aws-study-log.md）

セッション終了時（模試完了・演習終了時）に必ず追記する。無ければ作成する。タグは復習モードが集計に使うため、**必ず `タグ:` 行にサービス名をカンマ区切りで**書く。

```markdown
# AWS 学習ログ

## 進行中の模試
（中断時のみ記載。完了時に削除）

## セッション履歴

### 2026-07-04 | 模試 (SAA-C03) | 48/65 (74%)
- ドメイン別: セキュア 75% / 弾力性 71% / 高パフォーマンス 81% / コスト最適化 67%
- 間違えた問題:
  - Glacier の取り出し時間要件を読み落とし、Deep Archive を選択 | タグ: S3, Glacier
  - NAT ゲートウェイと VPC エンドポイントのコスト比較を誤答 | タグ: VPC, S3
  - IAM ポリシーの明示的 Deny の優先順位を誤答 | タグ: IAM
- 弱点サービス（累計タグ頻度上位）: S3 (5), VPC (4), IAM (3)
```

- 「弱点サービス」行は毎回、**過去ログ全体の `タグ:` 行だけを対象に**出現頻度を集計し直して更新する（「弱点サービス」行自体は集計に含めない。二重カウント防止）。
- 間違えた問題の要約は 1 行で「何を誤解したか」が分かる粒度にする（問題文の再掲は不要）。

## 復習モード

1. `aws-study-log.md` の全セッションからタグ頻度を集計し、上位 2〜3 サービスを特定する。
2. そのサービスを主題に、**過去に間違えた論点の類題**（同じ問題の再出題ではなく、同じ判断ポイントを別シナリオで問う）を中心に 10 問を演習モード形式で出題する。
3. 終了時、克服できた論点（今回正解した過去の弱点）をログに明記する。「本番直前の総ざらい」を頼まれたら、弱点タグ全部 + 正答率が最低のドメインを横断する 15〜20 問構成を提案する。
4. ログが無い状態で復習モードを頼まれたら、その旨を伝えてレベル確認（10問）を代わりに提案する。

## エッジケースの扱い

- **試験種別が未指定**: SAA-C03 をデフォルトとし、開始時に一言だけ断って進める（質問で止めない）。
- **中断・再開**: 上記「中断と再開」の通り。別セッション再開時は残り問題が新規生成になることを必ず伝える。
- **最新サービスとの乖離**: 料金の細かい数値や直近 1 年のアップデートが論点になる問題は避け、アーキテクチャ判断（サービス選定・設計原則）を問う問題を中心にする。ユーザーから知識より新しい情報を指摘されたら、素直に認めてその問題を採点から除外する。
- **回答形式が崩れた場合**（「2番目のやつ」「BかDで迷う」等）: 推測で採点せず、どの選択肢か確認する。「迷う」と言われたら模試モードではどちらかに決めてもらい、演習モードでは迷った理由を聞いてから解説する。
