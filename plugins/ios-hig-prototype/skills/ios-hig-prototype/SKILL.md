# ios-hig-prototype — iOS HIG 準拠プロトタイプ生成

アプリ情報から、Apple HIG に忠実な単一HTMLの動くiOSモックアップを作る。
デザイン・実装ルールの全文は `references/hig-prompt.md` に原文保存済みで、
この SKILL.md では重複させない。本体は「ヒアリング → 生成 → 検証」の運用手順に徹する。

## 工程1: ヒアリング

以下6項目を確認する。**未回答の項目があれば、生成前に必ず質問して埋める**
（推測で埋めて先に進まない。曖昧回答は仮置きした上で「〜として進めます、違えば教えてください」と明示）。

1. アプリ名
2. アプリの目的・概要
3. ターゲットユーザー
4. 主な機能（3〜5個）
5. 雰囲気・トーン（例: ミニマル/ポップ/信頼感/かわいい など）
6. アクセントカラーの希望（あれば。無指定ならアプリの世界観から1色選び、選定理由を報告に添える）

任意項目として「その他の要望（ダークモード対応、特定の画面が欲しい等）」も聞いてよいが、
これは必須6項目には含めない（無回答でも生成に進む）。

- ユーザーが依頼文に6項目のうち複数をまとめて書いてくることが多い。書かれている分は
  聞き直さず、抜けている項目だけをまとめて1回で質問する（1問ずつ往復しない）。
- 情報が極端に少ない依頼（「ToDoアプリ作って」だけ等）は、6項目のうち埋まっていないものを
  全部リストにして質問を返す。仮のダミー値で無断生成しない。

## 工程2: 生成

`references/hig-prompt.md` の【絶対条件】【iOSデザインの再現ルール】【実装する内容】
【出力の流れ】に厳密に従って単一HTMLファイルを生成する。読み込んだ上で、工程1で
集めたアプリ情報を当てはめて実行する。要点（詳細は参照ファイル側が正）:

- 単一HTML（CSS/JSインライン）。外部画像・外部フォント・外部CDNに依存しない
- **localStorage / sessionStorage 禁止**。状態は JavaScript 変数（メモリ内）のみで管理する
- 主要画面は3〜5画面。タブバーまたはナビゲーションで相互に行き来できる
- ダミーデータは日本語かつ具体的に書く（「サンプル1」「テキストテキスト」は禁止）
- 主要機能は最低1つ、実際に動く形で実装する（例: ToDoアプリなら追加・完了チェック・削除が本当に動く）
- 空状態（データ0件時）の画面を必ず用意する
- 出力順序: ①コンセプト・画面構成・アクセントカラー方針を3〜5行で説明 → ②HTML本体を出力
  → ③操作方法を2〜3行で案内

**出力先**: Artifact 相当の機能（claude.ai の Artifact、または本環境の Artifact ツール）が
使える場合はそちらに出力する。CLI 等で使えない場合は単一の `.html` ファイルとして書き出し、
そのまま開けば動く状態で渡す。

## 工程3: 検証

生成後、コードを出力して終わりにしない。以下を実施してから完成報告する。

1. **全ボタン・全遷移のトレース**: 実装したタブ/ボタン/リンクを一つずつ数え上げ、
   それぞれ「押すと何が起きるか」を頭の中で辿る。押しても何も起きない・遷移先が
   存在しない要素があれば実装し直す（ダミーのまま残さない）。
2. **空状態画面の確認**: 該当機能が0件時にどう表示されるか、実際にその状態で
   スタートした場合の見た目を確認する。
3. **絶対条件との再照合**: `references/hig-prompt.md` の【絶対条件】5項目
   （特に localStorage 不使用・単一HTML完結）を満たしているか最終チェックする。

検証で見つけた不備は報告前に直す。直せなかった既知の不備がある場合のみ、
報告の最後に「未対応: 〜」として明記する（黙って隠さない）。

## エッジケース

- **Android/Web調のデザインが要望に混ざる**（Material Design のFAB、ハンバーガーメニュー、
  ブラウザ的なUI等の指定）: 「HIG準拠と矛盾する」旨をユーザーに指摘し、iOS HIG に寄せるか
  要望通りAndroid/Web調にするか（その場合は本スキルの対象外である旨も添える）を確認してから進める。
  黙ってどちらかに寄せて生成しない。
- **画面数の希望が5画面を超える**: HIGプロトタイプとしての作り込み品質を優先し、3〜5画面に
  絞る提案をする。どうしても必要な場合のみ画面数を超えて実装してよいが、各画面の完成度を落とさない。
- **LP寄りの依頼（1枚の紹介ページ・訴求構成）と混同された場合**: lp-builder スキルの対象と
  伝え、切り替えを提案する。本スキルは複数画面・タブ/ナビゲーション遷移を持つアプリUIが対象。
- **アクセントカラー未指定**: 工程1で聞くが、それでも無指定なら systemBlue (#007AFF) を
  デフォルトとし、その旨を報告に明記する。

## 前提セットアップ

外部依存なし。API キー・MCP 不要。Artifact 出力ができない環境では単一 `.html` ファイル
書き出しにフォールバックする（工程2の「出力先」を参照）。
