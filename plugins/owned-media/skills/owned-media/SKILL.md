# Owned Media — SEO記事作成ワークフロー

オウンドメディアの記事を「キーワード選定 → 競合分析 → アウトライン → 執筆 → チェック」の
5工程で作るスキル。副業としての記事作成案件（クライアントあり）と、自分のメディア運営
（クライアントなし）の両方で使う。

**article-writer との違い**: article-writer は note 向けの自分の発信（読者は自分のフォロワー・SNS流入）。
このスキルは**検索エンジンからの流入を狙う SEO 記事に特化**しており、キーワードと検索意図を起点に
構成を組み立てる。「検索順位を上げたい・検索から集客したい」ならこちらを使う。

## いつ使うか

- 対策キーワードを指定されて（または決めるところから）SEO記事を新規作成するとき
- 順位が付かない・伸びない既存記事のリライトを頼まれたとき
- 記事は書かず、キーワード選定・記事企画リストだけ欲しいとき
- 構成案（アウトライン）だけ作ってクライアント確認に出すとき
- タイトル・メタディスクリプションなどメタ情報だけの改善依頼のとき

依頼内容に応じて工程を選ぶ。全部通す必要はない:

| 依頼 | 使う工程 |
|---|---|
| 新規記事をフルで | 工程1→2→3→4→5 |
| キーワード指定済みの新規記事 | 工程1（意図確認のみ）→2→3→4→5 |
| キーワード選定だけ | 工程1のみ |
| 構成案だけ | 工程1（意図確認）→2→3 |
| 既存記事のリライト | 工程2で現状記事と競合を比較 → 差分だけ3・4を実施 → 5 |
| メタ情報だけ | 工程5のタイトル・ディスクリプション項目のみ |

## 工程1: キーワード選定と検索意図の分類

1. 対象キーワードで WebSearch を実行し、**実際に上位に出ている記事のタイトルを見る**。
   検索意図はツールや推測ではなく、いま上位表示されているページの顔ぶれから判定するのが最も確実。
2. 検索意図を4分類する:

| 分類 | 意図 | 上位記事の傾向 | 記事の型 |
|---|---|---|---|
| Know | 知りたい | 「〜とは」「〜解説」 | 解説・網羅記事 |
| Do | やりたい | 「〜のやり方」「〜手順」 | 手順・チュートリアル記事 |
| Buy | 買いたい・比較したい | 「おすすめ」「比較」「ランキング」 | 比較・レビュー記事 |
| Go | 特定の場所・サイトに行きたい | 公式サイト・地図が上位 | **記事で狙わない**（公式に勝てない） |

3. サジェスト・関連キーワードの調べ方（キーワード選定だけの依頼ではここを厚く）:
   - WebSearch で「キーワード とは」「キーワード やり方」「キーワード おすすめ」「キーワード デメリット」
     などバリエーションを複数回検索し、出てくる記事タイトルに含まれる複合語を拾う
   - タイトルに繰り返し現れる語（例:「費用」「事例」「始め方」）がユーザーの関心＝サブキーワード候補
   - ラッコキーワード・Googleサジェスト等の外部ツールは、ユーザーが手元で引ける場合のみ結果を
     貼ってもらう（このスキル側の必須依存にはしない）
4. 選定結果は「キーワード / 想定意図(Know等) / 上位の顔ぶれ / 勝ち筋の有無」の表で出す。
   自分のメディア用なら、ドメインが弱い前提で**複合キーワード（3語以上）から狙う**ことを提案する。

**エッジケース — 検索意図が複数混在**（例: Know と Buy が上位に混ざる）:
1記事で両方は狙わない。上位10件のうち多数派の意図に記事の型を合わせ、少数派の意図は
「別記事として切り出す提案」を添える。混在比率が半々に近い場合はその旨を伝え、
どちらの読者を取るかをクライアント（自分メディアなら自分）に決めてもらってから工程2へ進む。

## 工程2: 競合分析 — 上位記事の構成を取る

1. WebSearch で対象キーワードを検索し、上位10件の URL・タイトルを一覧化する
2. 広告・地図・ECを除いた**記事コンテンツ上位5本**を対象に、WebFetch で H2/H3 見出し構成を抽出する
   - プロンプト例: 「この記事のH2・H3見出し構成をリストで抽出して」
3. **WebFetch が 403 等で失敗した場合（日本のメディアサイトではかなり頻発する）**:
   - 6位以下の取得できる記事で補充する
   - それでも5本集まらないときは、WebSearch のタイトル・スニペット＋工程1のバリエーション検索
     結果から共通トピックを**推定**で構成し、「見出しは実取得でなく推定」と成果物に明記する。
     取得失敗を理由に工程を止めない
4. 5本分の見出しを並べて2つを抽出する:
   - **共通トピック（＝必須要素）**: 3本以上が扱っている見出しテーマ。入れないと網羅性で負ける
   - **欠けている切り口（＝差別化要素）**: どの競合も扱っていないが検索者が知りたいはずの内容。
     自分・クライアントの一次情報（実体験、自社データ、失敗談）を当てられる切り口を優先する

**リライトの場合**: 現状記事の見出し構成も同じ形式で並べ、①必須要素のうち現状記事に無い見出し
（＝追加）、②競合の誰も扱わず検索意図にも合わない見出し（＝削除・統合候補）、③タイトル・
リード文が検索意図とズレていないか、の3点で差分表を作る。リライトはこの差分が工程3・4の入力になる。

**エッジケース — 上位が全て企業サイト**（ドメインパワー勝負になっている）:
正面から同じ構成で書いても個人・新規メディアでは勝てない。この場合は
①より具体的な複合キーワードへ対策をずらす（工程1に戻る）、②体験談・比較など企業サイトが
書きにくい一次情報型の切り口で差別化する、の2案を提示し、それでも元キーワードで書く指示なら
「上位表示の難易度が高い」旨をリスクとして成果物に明記した上で書く。

## 工程3: アウトライン作成

競合分析の結果から H2/H3 構成を作る。

- 構成の原則: リード文（検索意図への回答を先出し）→ 必須要素の H2 群（検索者の知りたい順）→
  差別化要素の H2 → まとめ（＋CTA: メディアの目的に応じて資料請求・関連記事など）
- **Buy意図（比較・レビュー記事）の追加原則**: 記事を作って終わりにせず「読者が迷わず
  行動できる導線」まで設計する。比較表は本文中に加えて記事冒頭付近にも配置を検討し、
  各商品の推奨シーンを明記する。CTA（購入・申込リンク）は比較表直下とまとめの両方に置き、
  「どれが自分に合うか」を数秒で判断できる形にする
- H2 は5〜8本、H3 は各 H2 に0〜4本が目安。H2 見出しには対策キーワードか
  サブキーワードを不自然にならない範囲で入れる
- 各見出しに「書く内容の1行メモ」と「根拠として使う情報源（一次情報 / 要WebSearch確認）」を付ける

**クライアント確認の分岐**:
- **副業案件**: アウトラインの段階で必ず一度提出して承認を得てから執筆に進む
  （執筆後の構成変更は手戻りが最大になるため）。提出物は「構成案＋対策KW＋想定検索意図＋
  想定文字数＋確認したい点」のセット。承認までは工程4に進まない
- **自分のメディア**: 確認は不要。ただしアウトラインを飛ばさず、書き始める前に
  検索意図とズレていないかセルフチェックだけ行う

## 工程4: 執筆

- **PREP を各 H2 の基本形にする**: 結論（Point）→理由（Reason）→具体例・データ（Example）→
  再結論（Point）。検索ユーザーは答えを探しに来ているので、各セクション冒頭で結論を言い切る
- **一次情報・体験を織り込む**: 実際に使った・やった・失敗した話、自社/クライアントのデータ、
  ヒアリングで得た事実。無ければ執筆前にクライアントへ「体験・実績として書ける素材はあるか」を
  確認する。素材ゼロの場合は公的統計・公式ドキュメントの引用で根拠を補強する
- **E-E-A-T を意識した根拠提示**: 数字・主張には出典（省庁統計、公式サイト、原典）を付ける。
  出典は WebSearch で実在と内容を確認してからリンクする。**未確認の統計値を書かない**。
  YMYL 領域（医療・金融・法律）は断定を避け、専門家監修が必要な旨をクライアントに伝える
- 文体: メディアのトンマナ指定に従う。指定が無ければ「です・ます調、1文60字以内目安、
  漢字をひらきすぎない」を初期値にして初稿で確認する

**エッジケース — 専門性の低いテーマの依頼**（自分に経験がない領域）:
体験を捏造しない。①競合分析＋公的情報ベースの「調査型記事」として書き、体験風の記述を入れない
②クライアント側の体験・事例をヒアリングして「素材はクライアント、構成と執筆はこちら」で作る、
のどちらで進めるかを執筆前に確認する。

**エッジケース — 文字数指定が過大**（例: 検索意図に対して2万字指定）:
文字数を埋めるための水増しは順位にもマイナスになり得る。競合上位5本の文字数感を根拠に
適正レンジを提示し、①適正文字数への変更、②1記事を分割して内部リンクで繋ぐトピッククラスター化、
を提案する。それでも指定通りの指示なら、FAQ・用語集・事例集など**検索者に意味のあるセクション**で
増やし、同じ内容の言い換えでは埋めない。

## 工程5: 公開前チェックリスト

- [ ] **タイトル**: 32字前後、対策キーワードを前半に、数字か具体性を1つ（3案出して選んでもらう）
- [ ] **メタディスクリプション**: 120字以内、キーワードを含め、クリックする理由（何が分かるか）を書く
- [ ] **見出し**: H2にキーワード/サブキーワードが自然に配置されているか。詰め込みすぎは減点対象
- [ ] **リード文**: 検索意図への回答（またはこの記事で分かること）が最初の3行以内にあるか
- [ ] **内部リンク**: 同メディア内の関連記事への発リンクを2〜3本提案する（リライト時は
      逆に「この記事へ張るべき既存記事」も挙げる）。リンク先が無ければ「次に書くべき記事」として提案
- [ ] **コピペ率への注意**: 競合の見出し・文をそのまま流用していないか。構成が競合とほぼ同一に
      なった場合は差別化セクションが機能しているか見直す。クライアントがコピペチェックツール
      （CopyContentDetector等）を使う前提なら、引用部は blockquote＋出典明記に統一する
- [ ] **出典**: 数字・固有の主張すべてにリンク or 出典名があるか
- [ ] **法令表現**: 「絶対」「必ず」「業界最安」等の断定・優良誤認表現がないか。健康・美容系は
      薬機法（効能効果の断定禁止）、金融系は金商法、価格・比較表現は景表法（優良誤認・有利誤認）
      の観点で見直す。アフィリエイト案件は PR 表記の要否を確認する。判断が難しい表現は
      「要人間確認」と明示し、断定的な効果表現には「個人の感想です」等の緩和表現を提案する

## 成果物フォーマット

納品物は必ず「記事本文＋メタ情報」のセットで出す。

```markdown
# メタ情報
- 対策キーワード: ◯◯（サブ: ◯◯、◯◯）
- 想定検索意図: Know（〜を知りたい人）
- タイトル案: ①… ②… ③…（推奨: ①）
- メタディスクリプション: …（120字以内）
- 想定文字数 / 実文字数: 6,000 / 6,240
- 内部リンク提案: [記事A]（H2「◯◯」から）、[記事B]（まとめから）
- 競合との差別化ポイント: …

# 記事本文
（H2/H3構造のMarkdown）
```

## 前提セットアップ

Claude Code 内蔵の WebSearch / WebFetch のみで動く。APIキー・MCP は不要。

| 項目 | 用途 | 備考 |
|---|---|---|
| WebSearch（内蔵） | 検索意図分類・競合特定・出典確認 | 必須。使えない環境では工程1・2が実行不可 |
| WebFetch（内蔵） | 競合記事の見出し抽出 | 403で弾かれるサイトが多い前提で工程2のフォールバックを使う |

検索順位の計測や Search Console 連携は将来拡張（現状は公開後の順位確認を手動で行う運用）。
