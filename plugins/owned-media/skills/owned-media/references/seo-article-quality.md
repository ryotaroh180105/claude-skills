# SEO記事の品質リファレンス — 評価される記事・画像配置・AIっぽさ回避

工程3（アウトライン）〜工程5（チェック）で、このファイルの該当節を参照する。

## 1. いま検索で評価される記事の前提（2025〜2026）

- **E-E-A-Tの筆頭はExperience（経験）**。実際に使った・やった一次情報の有無が、
  網羅性だけのまとめ記事との最大の差別化点。AI生成コンテンツが氾濫した結果、
  「誰でも書ける正しい記事」の価値は下がり続けている。
- Googleは「AIが書いたか」ではなく「検索者の役に立つか」で評価すると公言しているが、
  **量産型のAI定型文・体験ゼロの網羅記事は Helpful Content 系の評価で下がる**。
  AIで書くこと自体より「AIっぽい中身の薄さ」が問題。
- AI Overviews（検索結果上のAI回答）時代は、定義・一般論だけの記事はゼロクリックで
  読まれない。**AI回答に吸収されない要素**（一次体験、独自データ、詳細な手順スクショ、
  具体的な失敗例）を軸にする。

## 2. 読了される構成の型

- **リード文**: 最初の3行以内に「検索意図への回答 or この記事で分かること」。
  加えて「誰が書いているか（経験の根拠）」を1文入れると離脱が減る
  （例: 「実際に3社のツールを6ヶ月使い比べた結果をまとめる」）。
- **各H2はPREP**（SKILL.md 工程4のとおり）だが、**全セクションを同じ長さ・同じ
  リズムにしない**。重要なH2は厚く、前提の共有だけのH2は3行で終えてよい。
  均質さは読了率にもAIっぽさにも悪い。
- 1セクション（H2）はスマホ2〜3スクロール以内。超えるならH3で割るか記事を分ける。
- 流し読み前提で設計する: 見出し＋箇条書き＋表＋画像だけ拾って要旨が伝わるか。

## 3. 画像・図解の配置ガイド（アウトラインの段階で決める）

工程3のアウトラインで各H2に「画像案」を付け、工程4の執筆時は本文中に
`【画像: 種類＋内容の指示＋alt案】` を埋め込む。納品物の画像リストにも転記する。

### どこに・何を

| 位置 | 入れる画像 | 目的 |
|---|---|---|
| アイキャッチ/OGP | 記事テーマ＋タイトル要素の画像 | SNSシェア・検索結果での視認性 |
| リード文直後 or 最初のH2直下 | 記事全体の結論・全体像の図解（比較なら結論の表） | 答えを探しに来た検索者を最初の1画面で掴む |
| 概念・仕組みを説明するH2 | 関係図・フロー図（テキスト矢印でなく図解） | 文章3段落より図1枚のほうが滞在も理解も勝つ |
| 手順を説明するH2 | 1ステップ1スクリーンショット（操作箇所に赤枠・番号） | Do系クエリの核心。スクショの有無が再現性を決める |
| 比較・選定のH2 | 比較表（スマホで横スクロール可能な設計） | Buy系クエリの核心。表は強調スニペット獲得も狙える |
| データ・数字を根拠にする箇所 | グラフ（出典明記）または自社/自分の実測データ | 独自データはAI回答に吸収されない最強の差別化 |
| 体験談・レビューの箇所 | 現物写真（実際の画面、届いた商品、作業風景） | Experience の証明。ストック素材では逆効果 |

### 運用ルール

- 目安は**H2ごとに1枚以上、またはスマホ3スクロールに1枚**。
- **内容と無関係な装飾ストック素材は入れない**（握手・青空・外国人のオフィス風景）。
  情報を運ばない画像は離脱要因でしかない。
- 全画像にalt属性（画像の内容を具体的に。キーワード詰め込みはしない）。
- ファイル名は内容が分かる英数字（`keyword-step1-settings.png`）、容量圧縮
  （WebP等、1枚200KB目安）を納品時の注意として添える。
- スクショに個人情報・アカウント名が写り込んでいないかをチェック項目に含める。

## 4. 読みやすさの工夫

- 箇条書き: 並列の情報3点以上は文章にせず箇条書きへ。
- 表: 「AとBの違い」「〇〇の一覧」は必ず表。文章で書いた比較は読まれない。
- ボックス/引用: 注意点・補足はボックス化して本文の流れから分離（CMSの装飾指示として `【注意ボックス: …】` を書き込む）。
- 1文60字以内・漢字を開く・接続詞の連発を避ける（工程4の文体初期値と同じ）。

## 5. 評価を下げる要因（書かない・入れない）

- 文字数を稼ぐだけの「〜とは」の引き伸ばし、同じ内容の言い換え反復
- 検索者の課題に関係ない過剰な網羅（辞書化）
- 出典のない統計値・「〜と言われています」だけの根拠
- 体験風の記述の捏造（工程4のエッジケースのとおり、調査型に切り替えるかヒアリングする）

## 6. AIっぽさ回避チェックリスト（工程5に組み込む）

- [ ] **定型句**: 「いかがでしたか」「〜と言えるでしょう」「〜することが重要です（連発）」「近年、〜が注目されています（根拠なし）」「結論から言うと（毎H2）」がない
- [ ] **金太郎飴構成**: 全H2が同じ段落数・同じリズムで並んでいない。強弱があるか
- [ ] **一般論率**: 一次情報（体験・実測・ヒアリング・独自データ）がゼロのH2が続いていないか。ゼロの場合は公的統計＋具体的な数値・固有名詞で代替できているか
- [ ] **両論併記逃げ**: 「メリット・デメリットを踏まえて自分に合ったものを選びましょう」型の結論放棄で締めていない。読者の状況別に推奨を言い切っているか
- [ ] **機械的な並列**: どの見出しも必ず3点ずつ、のような不自然な均質さがない
- [ ] **音読テスト**: リード文とまとめを音読して、解説ロボットの日本語になっていないか
