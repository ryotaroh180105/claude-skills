# X投稿の品質リファレンス — 伸びる構造とAIっぽさ回避

執筆担当（③）とレビュー担当（④）は、投稿を書く/審査する前にこのファイルを読む。
「伸びる型に寄せる」と「アカウントのトーン&マナーを守る」が衝突したら戦略ファイルが優先。

このファイルの分析は、2026年4〜7月の日本語圏バズポスト（AI・キャリア・ビジネス・学び系の
個人アカウント、いいね数千〜68k）の x_search 実データ分析（2026-07-05実施）に基づく。
実例は末尾の「7. 分析ソース」を参照。

## 1. フック（1行目）— スクロールを止める

タイムラインでは1行目（と折りたたみ前の約2行）しか読まれない。1行目だけで
「読む理由」が立っていない投稿は本文がどれだけ良くても伸びない。

| 型 | 例（実データより） | 効く理由 |
|---|---|---|
| 断定・警告 | 「AIの言うことを全部信じちゃいけないよ」（68k likes） | 強い否定・線引きで即インパクト、自分ごと化 |
| リスト・数字 | 「怪物になるプロンプト5選」「自然化プロンプト30個」 | 即コピペ可能な価値の予告 → 保存を誘発 |
| 問いかけ | 「AI時代に今更HTML/CSSを勉強する意味ある？」 | キャリア不安を直接突き、リプライも誘発 |
| 自分語り・感情 | 「ChatGPTに自分の5年後を見せてみた。ガチで泣いた」 | 感情共有が警戒を解き、共感反応を集める |
| 意外性・逆説 | 「ローカルAIイラスト、簡単すぎて『努力してる』とは言えない」 | 常識を覆して手が止まる＋議論喚起 |
| 数字・実績 | 「3ヶ月で案件0→5件になった方法」 | 具体性が信頼と結果の予告になる |
| 損失回避 | 「知らないと確実に損する設定」 | 得より損のほうが強く刺さる |

- 1行目に結論かベネフィットの核を置く。「今日は〜について話します」型の前置きは削る。
- フックで釣って本文が答えない「釣りタイトル」は中期的にフォロー解除を招く。フックの約束は本文で必ず回収する。

## 2. 言葉遣い・トーン

- **口語で書く**。書き言葉（「〜である」「〜と考えられる」）はタイムラインで浮く。
  実データで伸びた投稿の語尾は「〜よ」「〜ないよ」「〜ある？」など親しみやすい断定・疑問形。
- **一文を短く**。読点で繋がず、短文の連続でリズムを作る（実データでは体言止め連発より
  短文多用が主流。体言止めは強調点に限定）。
- **漢字を開く**。漢字率が高いと画面が黒く見えて読み飛ばされる（目安: 漢字3割）。
  漢字は固有名詞・専門用語に残し、それ以外は開く。例: 「出来る→できる」「事→こと」「更に→さらに」。
- **言い切る**。「〜かもしれません」「〜と思ったりします」の多用は説得力を殺す。
  事実でないものは主語を自分にして言い切る（「僕はこれで変わった」）。
- **トーンは「先生」ではなく「同じ目線で教える先輩」**。上から解説せず、
  「触る前の理解で成果が変わる」「最後にこれを足すだけで別物」のような実感ベースの言い方にする。
- 絵文字は控えめが主流（視覚要素は画像添付で代用するのが伸びた投稿の傾向）。
  記号は箇条書きの「・」「①②③」を活用。**各行頭に機械的に絵文字を並べるのはAIっぽさの典型**。

## 3. 構成 — 結論先出しと視覚設計

```
1行目: フック（結論 or 引っかかり）
2行目〜: 根拠・具体例（体験談・数字・固有名詞）
（箇条書きを使うなら3〜5点。「・」で簡潔に）
最終行: 締め（要約の言い切り / 問いかけ / 次の行動）
```

- **空行で圧迫感を消す**。塊が4行を超えたら改行を検討。スマホでの見た目が全て。
- 長くなるならスレッド化。1ポスト目は単体で完結させ、「続きは↓」で繋ぐ。
- 締めの1行は「保存推奨」「あなたはどう思う？」など、**取りたい反応を1つ選んで**設計する。

## 4. 説得力 — どこで信じさせるか

- **数字・固有名詞・体験のどれかを最低1つ**入れる。3つともない投稿は「誰でも言える一般論」で、伸びないしAIっぽい。
- Before→After（「〜だった自分が、〜したら、〜になった」）は最短の証拠提示。
- 事実と意見を混ぜない。事実は出典（元ポスト・記事URL）、意見は「僕は」を付ける。
- 両論併記で結論をぼかさない。反論の余地があっても自分の立場を言い切るほうが反応は集まる（炎上リスク観点は④レビューで別途チェック）。

## 5. どの反応を取りにいくか（投稿設計の起点）

企画段階で「この投稿は何を取りにいくか」を1つ決め、構成をそれに合わせる。

| 狙い | 効く内容 | 構成の特徴 |
|---|---|---|
| 保存 | 手順・テンプレ・網羅リスト・設定集（「プロンプト◯選」型） | 箇条書き・即コピペ可能・「保存して後で見返して」 |
| 共有(RP) | 代弁（みんな思ってたこと）・驚きの事実・速報 | 言い切りの強い1〜2文完結型 |
| 共感(いいね) | 自己開示・失敗談・感情の告白・あるある | 語りかけ・オチのある小話 |
| リプライ・議論 | 問いかけ・意見が分かれるテーマへの明確な立場表明 | 締めが疑問文、または反論余地のある言い切り |

- 実データ上、最強の組み合わせは **「即実践可能な価値提供」＋「感情・議論の揺さぶり」**。
  議論が活発化した投稿はアルゴリズムがさらに露出を増やす好循環に入る
  （ただし炎上リスクは④レビューで必ず判定。反論誘発と攻撃は別物）。

## 6. AIっぽさ回避チェックリスト（X向け）

執筆後・レビュー時に以下を機械的に確認する。1つでも該当したら書き直し。
X投稿は短いぶん1つの定型句・1つの不自然さが目立ちやすいので、note/SEO記事以上に厳しく見る。

- [ ] **文末の逃げ表現・接客フレーズ**: 「〜と言えるでしょう」「いかがでしたか」「参考になれば幸いです」「素晴らしい〜ですね」がない
- [ ] **定型句**: 「〜が重要です」「〜が求められています」「これにより」「多岐にわたる」等の説明書調がない
- [ ] **両論併記逃げ**: 「一概に言えませんが」「場合によります」で逃げず、自分の立場を言い切っているか
- [ ] **金太郎飴構成**: きれいに3点ずつ並べる rule of three になっていない（点数・粒度が揃いすぎは不自然。X の短い箇条書きでも3点固定が続くと機械的に見える）
- [ ] **体験・数字・固有名詞ゼロの一般論**になっていない。時間・場所が特定できる具体的なエピソードがあるか
- [ ] **全文が均質な敬体で流れていない**（言い切り・体言止め・口語で崩れがあるか）。同じ文末表現の連続がないか
- [ ] 各行頭の機械的な絵文字・過剰なハッシュタグ（3個以上）がない
- [ ] 「AI・活用・効率化・重要・ポイント」等の抽象語だけで具体が語られていない箇所がない
- [ ] 読み上げたとき人がしゃべる日本語として自然か（音読テスト）
