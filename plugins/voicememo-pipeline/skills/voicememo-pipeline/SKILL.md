# voicememo-pipeline

録音ファイルを受け取り、①文字起こし → ②議事録整形 → ③会話フィードバック生成 →
④Google Drive 保存 → ⑤Slack 送信 まで一気通貫で行うスキル。
インターンでの MTG・商談同席の振り返りを主な用途として想定している。

## 前提セットアップ（最初に必ず確認する）

作業を始める前に、以下の3つの状態を確認する。未設定のものがあれば **必須項目はユーザーに設定を依頼して止まり**、任意項目はその工程をスキップしてローカル保存にフォールバックする。

| 項目 | 必須/任意 | 確認方法 | 未設定時の挙動 |
|---|---|---|---|
| `OPENAI_API_KEY` | **必須** | `echo ${OPENAI_API_KEY:+set}` が `set` を返すか | 文字起こし不可。https://platform.openai.com/api-keys でキーを発行し `export OPENAI_API_KEY=sk-...` を設定するようユーザーに案内して止まる |
| Google Drive MCP | 任意 | `mcp__Google_Drive__*` ツールが使えるか | Drive へのアップロード/ダウンロードをスキップし、成果物はローカル保存のみ。その旨をユーザーに伝える |
| `SLACK_WEBHOOK_URL` | 任意 | `echo ${SLACK_WEBHOOK_URL:+set}` が `set` を返すか | Slack 送信をスキップ。送信予定だった本文をそのまま画面に出し、手動コピペできるようにする |

キーが未設定でも `--dry-run` での動作確認（後述のスモークテスト）はできる。

## ワークフロー

### ① 音声ファイルの受領

- **ローカルパスの場合**: そのまま次へ。存在確認は transcribe.py が行う。
- **Google Drive 上のファイルの場合**: `mcp__Google_Drive__search_files` でファイルを特定し、`mcp__Google_Drive__download_file_content` でローカル（作業ディレクトリ）にダウンロードしてから次へ。Drive MCP が未接続なら、ファイルを手動ダウンロードしてパスを教えてもらうよう依頼する。
- 対応形式: flac / m4a / mp3 / mp4 / mpeg / mpga / oga / ogg / wav / webm

あわせてユーザーに軽く確認しておくと後工程の質が上がる:
会議の種別（社内MTG / 商談 / 音声メモ）、参加者名、フィードバックが欲しいか。
音声メモ（ひとり録音）の場合は議事録ではなく「要点メモ」形式にし、フィードバック工程（④）は省略する。

### ② 文字起こし（scripts/transcribe.py）

このスキルの `scripts/transcribe.py` を実行する（標準ライブラリのみで動作、追加インストール不要）:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/voicememo-pipeline/scripts/transcribe.py" \
  /path/to/meeting.m4a --language ja --out ./meeting_transcript.txt \
  --prompt "山田,佐藤,株式会社アクメ"   # 参加者名・社名を渡すと固有名詞の精度が上がる（任意）
```

- モデルは `whisper-1`（`--model` で変更可）。結果は `--out`（省略時 `<音声名>_transcript.txt`）に保存される。
- 終了コード: 0=成功 / 1=ファイル・引数エラー / 2=キー未設定 / 3=APIエラー。エラーメッセージに対処方法が日本語で出るので、それに従う。
- 実行後、出力ファイルを読み込んで次工程へ。長い場合も全文を読むこと（決定事項の見落とし防止）。

### ③ 議事録整形

文字起こし全文を読み、以下のテンプレートで `meeting_minutes.md` を作る。埋められない項目は「不明（要確認）」と書き、勝手に創作しない。日時が音声から分からなければファイルの日付かユーザーへの確認で補う。

```markdown
# 議事録: <会議名>
- 日時: YYYY-MM-DD HH:MM〜HH:MM
- 参加者: <名前（役割）>
- 記録: voicememo-pipeline (自動生成・要確認)

## 議題
1. ...

## 議論の要点
- ...

## 決定事項
- ...

## TODO
| # | タスク | 担当 | 期限 |
|---|---|---|---|
| 1 | ... | ... | YYYY-MM-DD / 未定 |

## 保留・次回持ち越し
- ...
```

### ④ 会話フィードバック生成（商談・MTG同席の振り返り用）

ユーザー（Ryo）の発言に注目して `meeting_feedback.md` を作る。文字起こしに話者ラベルは無いので、文脈からユーザーの発言を推定し、確信が持てない場合は「あなたの発言と思われる箇所」と断る。観点:

1. **良かった点**: 具体的な発言を引用して2〜3個（次も再現できるように理由付き）
2. **話し方**: 結論ファーストか、冗長な前置き・フィラー（「えっと」等）、話す量のバランス
3. **質問の質**: オープン/クローズドの使い分け、深掘りできたか、確認質問（認識合わせ）の有無
4. **改善提案**: 次の商談/MTGで試す具体的アクションを3個以内（多すぎると実行されない）

トーンは率直かつ建設的に。抽象論ではなく必ず文字起こしからの引用を根拠にする。

### ⑤ Google Drive 保存（MCP 接続時のみ）

`mcp__Google_Drive__create_file` で `meeting_minutes.md` と `meeting_feedback.md` をアップロードする。保存先フォルダはユーザーに確認（初回に決めたら以後同じ場所）。文字起こし全文（transcript）も残すか聞いてから上げる。
**MCP 未接続なら**: スキップし、「ローカルの `meeting_minutes.md` / `meeting_feedback.md` に保存済み。Drive 連携するには Google Drive MCP を接続してください」と伝える。

### ⑥ Slack 送信（SLACK_WEBHOOK_URL 設定時のみ）

議事録の要約を Incoming Webhook に POST する。**フィードバック（④）は本人向けなので Slack には送らない**（ユーザーが明示的に頼んだ場合を除く）。

```bash
curl -sS -X POST "$SLACK_WEBHOOK_URL" -H 'Content-Type: application/json' -d @- <<'EOF'
{
  "text": "📝 *議事録: <会議名>* (YYYY-MM-DD)\n*決定事項*\n• ...\n• ...\n*TODO*\n• <タスク>（担当: <名前> / 期限: <日付>）\n\n全文: <Drive リンク or ローカル保存>"
}
EOF
```

送信前に本文をユーザーに見せて確認を取る（社内チャンネルに誤送信しないため）。
**未設定なら**: スキップし、上記 JSON の `text` 相当の本文を画面に出力して手動投稿できるようにする。

## エッジケース

| 状況 | 挙動 |
|---|---|
| 音声ファイルが存在しない | transcribe.py が exit 1 で「見つからない」と出す。パスを再確認し、Drive 上ならダウンロードから やり直す |
| 25MB 超のファイル | transcribe.py が exit 1 で ffmpeg の分割コマンド（10分ごと・必要なら64kbps圧縮）をそのまま表示する。案内どおり分割 → 各 part を順に文字起こし → 出力を時系列順に連結してから③へ。ffmpeg が無ければ `apt-get install ffmpeg` 等の導入を案内 |
| 対応外フォーマット（.aac, .wma, .mov 等） | transcribe.py が exit 1 で対応形式一覧と ffmpeg 変換コマンド例を表示する。変換してから再実行 |
| `OPENAI_API_KEY` 未設定 | transcribe.py が exit 2 でキーの発行 URL と export 手順を表示して止まる。キー設定をユーザーに依頼し、それまで後工程に進まない |
| API エラー（401/429 等） | 401=キーの値が不正、429=レート制限/残高不足、とメッセージに出る。原因をユーザーに伝えて指示を仰ぐ |
| Google Drive MCP 未接続 | ⑤をスキップしローカル保存のみ。①で Drive ダウンロードが必要な場合は手動ダウンロードを依頼 |
| `SLACK_WEBHOOK_URL` 未設定 | ⑥をスキップし、投稿用本文をそのまま出力 |
| 音声メモ（ひとり録音） | 議事録テンプレートではなく「要点 / アイデア / TODO」の簡易メモ形式にし、④は省略 |

## スモークテスト（キー設定前でも実行可）

初回セットアップ時や動作が怪しいときは、API を呼ばない `--dry-run` で検証する:

```bash
# 中身のあるダミーファイルを用意して実行（0 バイトのファイルは検証で弾かれるので touch は不可）
printf 'dummy' > ./sample.m4a
python3 "${CLAUDE_PLUGIN_ROOT}/skills/voicememo-pipeline/scripts/transcribe.py" \
  ./sample.m4a --dry-run
```

期待される出力: エンドポイント・model・language・ファイルサイズ・出力先・`OPENAI_API_KEY` の設定状態が表示され、`[dry-run] 検証 OK` で終了コード 0。
ここまで通れば、あとは実際の音声ファイルと有効な API キーで本実行するだけで end-to-end が動く。

## 完了報告の形

パイプライン完了時は以下をまとめて報告する:

- 生成物: 文字起こし / 議事録 / フィードバックの各ファイルパス（Drive 保存時はリンクも）
- Slack: 送信した/スキップした（理由）
- スキップした工程と、有効化に必要な設定（例: 「Slack 送信は `SLACK_WEBHOOK_URL` 設定で有効になります」）
- 議事録の TODO 一覧（ユーザーがすぐ次アクションに移れるように）
