# Model Switcher

タスク種別に応じて使う Claude モデルを判断・切り替えるスキル。目的は**コスト効率**——
「良いモデルは難しい仕事にだけ使う」。逆に、失敗コストの高い仕事を安いモデルで
やってやり直すのが一番高くつく。過剰スペックと過小スペックの両方を防ぐ。

## 発動条件

以下のタイミングでこのスキルの判断基準を適用する:

- **セッション開始時・タスク切り替え時**: 「今からやるタスクはどのモデル相当か」を
  下の分類表で判定する。現在のモデルが過剰スペック（例: データ整形を Fable でやろうと
  している）なら、切り替えを**提案**する（勝手に切り替えず、理由とコスト差を添えて確認する）。
- 大量の定型処理・データ整形・一括変換を頼まれた時（→ Haiku 委譲を検討）。
- 設計・要件定義・難デバッグ・スキル作成が始まった時（→ Fable/Opus か確認）。
- ユーザーから「モデルどれがいい？」「API 代が高い」「コスト見直したい」と聞かれた時。
- 2026-07-07（Fable 無料期間終了）以降のデフォルト構成を相談された時。

## 現行モデルラインナップ（2026-07 時点。この表を正とし、古いモデル名を使わない）

| モデル | モデル ID | 入力 $/1M | 出力 $/1M | 位置づけ |
|---|---|---|---|---|
| Claude Fable 5 | `claude-fable-5` | $10 | $50 | 最上位。**2026-07-07 まで無料期間中**（期間中は実質コストゼロ） |
| Claude Opus 4.8 | `claude-opus-4-8` | $5 | $25 | 高性能。難しい仕事の常用上限 |
| Claude Sonnet 5 | `claude-sonnet-5` | $3（〜2026-08-31 は $2） | $15（同 $10） | 速度と知性のバランス。日常の主力 |
| Claude Haiku 4.5 | `claude-haiku-4-5-20251001` | $1 | $5 | 最速・最安。定型処理・大量処理用 |

- 目安: 同じ仕事を Fable でやると Haiku の**約 10 倍**、Sonnet の**約 3 倍**のコスト。
- `claude-3-5-sonnet` や `claude-sonnet-4` 系などの旧モデル名は書かない・提案しない。

## タスク分類 → モデル選択表

| タスク種別 | 推奨モデル | 理由 |
|---|---|---|
| アーキテクチャ設計・技術選定 | Fable 5 / Opus 4.8 | 判断ミスが後工程全体に波及する（失敗コスト大） |
| 難しいデバッグ・原因調査 | Fable 5 / Opus 4.8 | 深い推論が必要。安いモデルで迷走する方が高くつく |
| スキル作成・プロンプト設計 | Fable 5 / Opus 4.8 | 成果物が再利用され続けるため品質が波及する |
| 要件定義・仕様の壁打ち | Fable 5 / Opus 4.8 | 曖昧さの解消は判断の難しさが高い |
| 通常のコーディング・リファクタ | Sonnet 5 | 十分な品質で 1/3 のコスト |
| 記事執筆・ドキュメント作成 | Sonnet 5 | 文章品質と速度のバランスが良い |
| コードレビュー・PR チェック | Sonnet 5 | 定常業務。難所だけ上位モデルに切り替え |
| 大量データ整形・一括変換 | Haiku 4.5 | 判断がほぼ不要で回数が多い。単価が支配的 |
| 定型的な要約・分類・簡単な応答 | Haiku 4.5 | 1 件あたりの価値が低く、失敗しても安く再試行できる |

「Fable 5 / Opus 4.8」の使い分け: **無料期間中（〜2026-07-07）は Fable**。
それ以降はまず Opus 4.8 を使い、Opus で行き詰まった最難関のタスクだけ Fable に上げる。

### 判断基準（表にないタスクはこの 3 つの質問で決める）

1. **失敗コストは高いか？** — 間違えるとやり直し・手戻り・信頼低下が大きい仕事は
   上位モデル。間違えても安く再実行できる仕事は下位モデル。
2. **試行回数は多いか？** — 同じ処理を何十回・何百件も回すなら、単価の安さが効く。
   下位モデルに寄せる（回数 × 単価で総コストを見積もる）。
3. **判断は難しいか？** — 曖昧さの解消・トレードオフの比較・長い推論が必要なら
   上位モデル。手順が明確で機械的なら下位モデル。

判定ルール: **1 か 3 が「はい」なら Fable/Opus、2 だけ「はい」なら Haiku、
すべて「いいえ」〜中程度なら Sonnet**。迷ったら Sonnet から始めて、詰まったら上げる。

## 切り替え方法

### ① セッション全体を切り替える: `/model` コマンド

今のセッションで使うモデルをその場で変える。タスクの難易度が変わった瞬間に使う。

```
/model                    # 対話メニューから選択
/model claude-sonnet-5    # モデル ID を直接指定
/model opus               # エイリアス指定（opus → Opus 4.8）
/model haiku              # エイリアス指定（haiku → Haiku 4.5）
```

使い所の例: 設計相談が終わって実装フェーズに入ったら `/model claude-sonnet-5`、
実装中に難しいバグに当たったら `/model opus` に上げ、解決したら戻す。

### ② プロジェクトの既定モデル: `.claude/settings.json` の `model`

そのプロジェクトで Claude Code を起動した時のデフォルトを決める。
「このリポジトリの作業はほぼ定常コーディング」なら Sonnet を既定にしておく。

```json
{
  "model": "claude-sonnet-5"
}
```

- プロジェクト共有なら `.claude/settings.json`、自分だけなら `.claude/settings.local.json` に書く。
- 個々のセッションでは①の `/model` で一時的に上書きできる。

### ③ サブエージェント単位: Agent tool の `model` パラメータ / agents frontmatter

**安いモデルへの大量作業委譲パターン**。メインセッションは上位モデルのまま、
機械的な作業だけサブエージェントに切り出して Haiku で実行する。
メイン側のモデルもコンテキストも汚さずに単価だけ下げられるのが利点。

Agent tool でその場で指定する場合（`model` パラメータに `haiku` / `sonnet` / `opus` を渡す）:

```
Agent tool 呼び出し時:
  subagent_type: general-purpose
  model: haiku
  prompt: data/ 配下の CSV 30 ファイルすべてのヘッダー行を snake_case に統一して保存する
```

繰り返し使う定型エージェントは `.claude/agents/*.md` の frontmatter に固定する:

```yaml
---
name: bulk-formatter
description: 大量ファイルの機械的な整形・変換を担当する。判断を伴う修正はしない。
model: haiku
---

渡されたファイル群を指示どおりに整形する。仕様が曖昧な箇所は変更せず報告に回す。
```

委譲の目安: 「対象が 10 件以上」×「1 件ごとの手順が同じ」×「判断が要らない」が
そろったら Haiku サブエージェントに出す。1 件でも判断が要る箇所が混ざるなら、
その箇所だけメイン（上位モデル）で処理し、残りを委譲する。

### ④ 設計・監査はメイン（上位モデル）、実装はサブエージェント（下位モデル）に切り出す

Haiku 委譲（③）が「機械的な大量作業」の切り出しなら、こちらは
**「難易度は高いが手を動かすだけの実装」**をサブエージェントに渡すパターン。
メインセッション（Fable/Opus）は設計・仕様確認・レビューに専念し、実装そのものは
Sonnet/Opus のサブエージェントにやらせることで、上位モデルの単価が高い時間を
「判断」だけに使う。

指示例（Fable/Opus セッションの冒頭で宣言する）:

```
実装にあたってはトークンを節約するためにOpus/Sonnetを適切にサブエージェントとして
切り出して実行し、このメインセッション(Fable 5)は設計と監査、レビューに専念して
ください。実装難易度が特に高いところはこのセッションでやってよいです
```

### ⑤ 采配の型「10-80-10」（Fable/Opus 無料枠・高単価期の使い方）

1セッションの作業を3フェーズに分け、上位モデルを使うのは最初と最後の10%だけにする:

| フェーズ | 割合 | やること | モデル |
|---|---|---|---|
| 設計 | 最初の10% | 要件整理・方針決定・ルール決め | Fable 5 / Opus 4.8 |
| 実行 | 中間の80% | 下書き・探索・整形・実装 | Sonnet 5（③④で委譲） |
| 検収 | 最後の10% | レビュー・検証・最終判断 | Fable 5 / Opus 4.8 に戻す |

引き継ぎの合図は「上位モデルの答えを**ファイル（型・設計書・SKILL.md 等）に固定した瞬間**」。
設計をファイルに焼き付けたら、以降の実行フェーズは下位モデルに委ねてよい。
安いモデルに全部投げるのではなく、判断が要る入口と出口だけ高いモデルを使う考え方。

## Fable / Opus 使用時の自動適用: token-saver + yagni-guard

**Fable 5 / Opus 4.8 を開発タスク（コーディング・設計・デバッグ・スキル作成等）で
使う、または使うと確認が取れた時点で、ユーザーの追加指示を待たずに
`token-saver`（full）と `yagni-guard`（full）を併用する。** 単価が最も高い
モデルだからこそ、応答の無駄・過剰実装によるコスト増を一番避けたい場面のため。

- `/model claude-fable-5` / `/model opus` に切り替えた、または現在のモデルが
  Fable/Opus で開発作業を続ける、と判定した瞬間に両スキルを適用開始する。
- Sonnet / Haiku に切り替えたら、この自動適用は終了してよい
  （ユーザーが明示的に「caveman/ponytail 続けて」と言えば継続する）。
- 適用中の具体的な振る舞いは各スキル本体を参照:
  `plugins/token-saver/skills/token-saver/SKILL.md` /
  `plugins/yagni-guard/skills/yagni-guard/SKILL.md`。

## 運用ルール

1. **タスク開始前に必ず 1 回判定する**。分類表 → 3 つの質問の順で、今のモデルと
   推奨モデルを比べる。一致していれば何も言わずに作業を続けてよい。
2. **過剰スペックなら提案する**。例: 「この整形作業は Haiku で十分です（コスト約 1/10）。
   `/model haiku` に切り替えるか、Haiku のサブエージェントに委譲しますか？」
   のように、根拠（タスク種別）とコスト差を 1 行で添える。
3. **過小スペックでも提案する**。設計・難デバッグを Sonnet/Haiku でやっていたら
   「失敗コストが高いので Opus 以上を推奨」と伝える。安物買いのやり直しが最も高い。
4. **切り替えは細かくやりすぎない**。1 セッション内で頻繁に往復すると
   プロンプトキャッシュが無効化されて逆に割高になる。フェーズの境目
   （設計→実装、実装→一括処理）でだけ切り替える。細かい混在はサブエージェント（③）で解決する。
5. **無料期間中（〜2026-07-07）の特例**: Fable が無料の間はメインセッションを
   Fable のままにしてよい。ただし Haiku 委譲パターン（③）は無料期間中から練習しておく。

## 2026-07-07 以降の推奨構成（Fable 無料期間終了後）

無料期間が終わったら「全部 Fable」から次のデフォルトに移行する:

| 用途 | モデル | 設定方法 |
|---|---|---|
| 普段の作業（既定） | Sonnet 5 | `.claude/settings.json` に `"model": "claude-sonnet-5"` |
| 設計・難デバッグ・スキル作成の難所だけ | Fable 5 / Opus 4.8 | その場で `/model claude-fable-5` または `/model opus`、終わったら戻す |
| バルク処理・定型サブタスク | Haiku 4.5 | サブエージェントの `model: haiku` 指定 |

- コスト感度が高い場合は難所も Opus 4.8 を上限にする（Fable の半額。多くの難所は Opus で足りる）。
- 移行チェックリスト: ①各プロジェクトの `settings.json` の `model` を確認・設定
  ②よく使う定型エージェント（`.claude/agents/*.md`）に `model: haiku` を明記
  ③1〜2 週間後に使用量を振り返り、「Sonnet で詰まった回数」が多ければ難所の
  切り替え基準を緩める（早めに上位モデルへ）。

## 外部依存

なし。Claude Code 標準機能（`/model`、settings.json、サブエージェント）のみで動く。
