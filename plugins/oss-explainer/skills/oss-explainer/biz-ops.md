# oss-explainer ビジネス運用面シート

- 一文価値提案: 独学IT就活生が、ChatGPTの受け売りに頼らず、バズOSSを根拠付きで読み解いた解説note記事を書ける
- 想定ユーザー（3人）: Ryo本人 / 同層の独学IT就活生 / （仮置き）技術発信したいインターン仲間
- 代替手段と乗り換え理由（1点）: ChatGPTに直接聞く → 本スキルはリポジトリ実読解＋事実裏取り＋自分の文体で記事化まで繋がる
- 導入: 手順数 3 / 所要 5分 / 前提条件: hermes-relay 既設（他スキル共通）、GitHub MCP or WebFetch
- 保守: 予算 週10分 / 壊れる要因: GitHub MCP・WebFetch のIF変更 / hermes-relay 停止 / article-writer 工程変更 / 廃止基準: ユーザー0が2ヶ月 or 保守2回連続超過
- 運用: 定常作業: なし（依頼駆動） / 失敗通知経路: 依頼セッション内で取得失敗を即報告 / 1利用あたりコスト: hermes-relay 1往復（既存サブスク内）＋MCP/WebFetch（無料枠）
- 配布チャネルと最初の10ユーザー（到達期限: 公開後4週）: 生成した解説記事を note 公開し記事内でスキルに言及（記事＝配布物）
- 収益/回収: 直接収益なし。note発信の実績・ポートフォリオ・就活エピソード（G3）で回収
- 記録する指標: 新規に作った記事数 / 記事の再利用（連載化）/ 記事経由の反応（スキ・フォロー）＋ドッグフーディング（自分で作った本数）
- 意図的に無視すること: 想定ユーザーが実質Ryo圏内である点（G3割り切り）/ 有料記事・連載自動化（実需が出てから）/ リポジトリのローカル実行検証（静的読解で足りる）
- 悪魔の代弁者: 指摘3件→処理: ①「ChatGPTで十分」→根拠URL付き裏取りと文体一貫で差別化（事実台帳を必須化）②「読解が浅くなる」→読解順固定＋読んだ根拠明示を強制 ③「article-writerと重複」→執筆を全委譲し出口をbrief引き渡しに固定
